# 4. Tensors — The Data Structure Behind Everything

You've learned about tokens (integers), embeddings (lists of floats), and the embedding matrix (a big table of those lists). But there's a word you'll encounter everywhere once you step into actual ML code — a word that wraps all of these ideas into one unified concept.

That word is **tensor**.

A tensor isn't some exotic mathematical object. It's just a container for numbers, organized in a grid of a specific shape. Once you understand what a tensor is and how to read its shape, you'll be able to look at any piece of ML code and immediately understand what data is flowing through it.

---

## From Scalars to Tensors

The easiest way to understand tensors is to start from what you already know and add one dimension at a time.

**A scalar** is a single number. Temperature is 23. A loss value is 0.47. No dimensions, just one value.

```
scalar = 42
shape: ()    ← zero dimensions, just a number
```

**A vector** is a list of numbers — one dimension. An embedding is a vector: `[0.234, -0.512, 0.891, ...]`. A row of data is a vector. An index into a list is a vector of length 1.

```
vector = [0.2, -0.5, 0.8, 1.1]
shape: (4,)   ← one dimension, 4 elements
```

**A matrix** is a grid of numbers — two dimensions, rows and columns. The embedding matrix is a matrix: 50,000 rows (one per token), 768 columns (one per dimension).

```
matrix = [[1, 2, 3],
           [4, 5, 6]]
shape: (2, 3)   ← 2 rows, 3 columns
```

**A tensor** is the generalization to any number of dimensions. A 3D tensor might be a batch of matrices. A 4D tensor might be a batch of images (batch × height × width × channels).

```
tensor_3d shape: (batch_size, seq_len, emb_dim)
             e.g. (32, 128, 768)
             ← 32 sentences, each 128 tokens, each token a 768-dim vector
```

![Tensors: add one axis at a time. 0-D scalar 42; 1-D vector of three floats; 2-D matrix of two tokens × three dims; 3-D batch of two sentences (“the cat”, “a dog”). The residual stream of a Transformer is (B, T, d) — batch × tokens × channels.](/appendix-a/04-tensors/ranks-0d-to-3d.png)

Every number inside a neural network — every input, every weight, every intermediate result — lives in a tensor. The shape tells you exactly what the dimensions represent.

## Shape Is Everything

When ML engineers read code, the first thing they check on any tensor is its shape. Shape = `(d₀, d₁, d₂, ...)` where each number is how many elements exist along that dimension.

Here's how the concepts you've already learned map to tensor shapes:

| What it is | Tensor shape | Meaning |
|:-----------|:------------|:--------|
| A single token ID | `()` scalar | One integer |
| One embedding vector | `(768,)` | 768 floats |
| One tokenized sentence | `(seq_len,)` | e.g. `(47,)` — 47 token IDs |
| Embedding matrix | `(vocab_size, emb_dim)` | e.g. `(50257, 768)` |
| One sentence, embedded | `(seq_len, emb_dim)` | e.g. `(47, 768)` |
| A batch of sentences | `(batch, seq_len, emb_dim)` | e.g. `(32, 47, 768)` |

That last one — `(batch, seq_len, emb_dim)` — is the shape of the main tensor that flows through a Transformer. 32 sentences, each 47 tokens long, each token represented as a 768-dimensional vector. Three numbers tell you the entire structure of what the model is processing.

## Data Types: What's Inside the Tensor

Tensors store different kinds of numbers depending on what they're used for.

**`int64` (integers)** — for token IDs. Token IDs are just indices; they're always whole numbers. No need for decimal precision.

**`float32` (32-bit floating point)** — for almost everything else: embedding values, model weights, attention scores, loss values. Most training and inference runs on float32.

**`float16` / `bfloat16` (16-bit floating point)** — half-precision. Uses half the memory and runs faster on modern GPUs. Slightly less precise, but the precision loss is acceptable for most operations. Most large model inference runs in `bfloat16`.

**`bool`** — for masks. When you want to tell the model "ignore these positions" (e.g. padding tokens), you pass a boolean mask tensor the same shape as the sequence: `True` = pay attention, `False` = ignore.

## Indexing and Slicing

Tensors are indexed exactly like Python lists, but across multiple dimensions at once. This is how lookup operations, attention masking, and batch processing all work under the hood.

    {

      "source": "import numpy as np\n\n# A (3, 4) matrix — 3 tokens, each with a 4-dim embedding\nM = np.array([\n    [0.1, 0.2, 0.3, 0.4],   # token 0\n    [0.5, 0.6, 0.7, 0.8],   # token 1\n    [0.9, 1.0, 1.1, 1.2],   # token 2\n])\nprint(f'Matrix M, shape {M.shape}:')\nprint(M)\nprint()\n\n# Single element\nprint(f'M[1, 2]   = {M[1, 2]}   (row 1, column 2)')\n\n# Entire row (one token's embedding)\nprint(f'M[0]      = {M[0]}   (all dims of token 0)')\n\n# Slice of rows (tokens 0 and 1 only)\nprint(f'M[:2]     =\\n{M[:2]}   (first 2 tokens)')\n\n# Slice of columns (first 2 dims of all tokens)\nprint(f'M[:, :2]  =\\n{M[:, :2]}   (first 2 dims, all tokens)')\n\n# Fancy indexing: pick specific rows by index list\n# This is exactly what embedding lookup does\nidx = np.array([2, 0, 1])   # reorder tokens\nprint(f'M[idx]    =\\n{M[idx]}   (tokens in order: 2, 0, 1)')",

That last operation — `M[idx]` where `idx` is an array of indices — is **exactly** the embedding lookup from Chapter 3, expressed in tensor notation. When the model looks up embeddings for a sequence of token IDs, it's doing one fancy index operation on the embedding matrix.

## A Note on Naming

The same model dimension appears under four different names depending on whose code you're reading. This trips up everyone who moves between papers and codebases.

| What it means | GPT-2 | HuggingFace | Papers | This book |
|:---|:---|:---|:---|:---|
| Embedding / hidden dimension | `n_embd` | `hidden_size` | `d_model` | `d_model` |
| Number of attention heads | `n_head` | `num_attention_heads` | `h` | `num_heads` |
| Number of layers | `n_layer` | `num_hidden_layers` | `N` | `num_layers` |
| Context length | `n_ctx` | `max_position_embeddings` | `n` | `seq_len` |

They all refer to the same quantities — GPT-2's `n_embd=768` is HuggingFace's `hidden_size=768` is the papers' `d_model=768`. When you see an unfamiliar name in a config file or paper, check this table first.

## Quick Recap

- A **tensor** is a container for numbers organized in N dimensions. Scalar (0D), vector (1D), matrix (2D), 3D+.
- **Shape** — e.g. `(32, 128, 768)` — tells you what each dimension represents. Reading shapes is the core skill for understanding model code.
- The main tensor flowing through a Transformer is `(batch_size, seq_len, emb_dim)`.
- **dtypes**: token IDs use `int64`; embeddings and weights use `float32` (training) or `float16`/`bfloat16` (inference).
- Indexing, slicing, and fancy indexing work across all dimensions. The embedding lookup is just `emb_matrix[token_ids]`.

You now speak the language that all neural network code is written in. The next chapter shows what you actually *do* with these tensors once you have a few hundred million of them.
