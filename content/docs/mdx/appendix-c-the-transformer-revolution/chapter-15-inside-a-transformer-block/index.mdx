# 15. Inside a Transformer Block

The last three chapters built attention piece by piece: scaled dot-product attention, multiple heads, and position information. Attention alone isn't a model, though. A Transformer is one **block** repeated N times — 12 in GPT-2 small, 32 in Llama-3-8B, 126 in Llama-3-405B — and each block wraps attention in three more ingredients: a **feed-forward network**, **residual connections**, and **layer normalization**.

The original paper is Vaswani et al. (2017), *Attention Is All You Need*. Everything in this chapter is that architecture, looked at one piece at a time.

Each one fixes a specific problem. Attention moves information between tokens but does little computation on it — the FFN does that. Deep stacks are hard to train — residual connections make the gradient's path short. Activations drift in scale from layer to layer — normalization pins them down. This chapter takes the block apart, puts it back together in code, counts every parameter of GPT-2, and ends with how the 2024 version of the block differs from the 2019 one.

---

## The block at a glance

Here is the block used by GPT-2, GPT-3, Llama and almost every model since — the "Pre-LN" decoder block:

$$
h = x + \operatorname{MHA}\!\big(\operatorname{LN}(x)\big), \qquad
y = h + \operatorname{FFN}\!\big(\operatorname{LN}(h)\big)
$$

Two sub-layers, each with the same wrapping: normalize a copy of the input, transform it, and **add** the result back to the input.

- **Masked multi-head attention** lets tokens exchange information ("which earlier tokens matter for this one?").
- The **feed-forward network** processes each token on its own ("now that I've gathered context, what does it mean?").

Input and output have the same shape, $n \times d_{\text{model}}$, so blocks stack like Lego.

![One Transformer block (GPT-style, Pre-LN). Left: the data flow — x (seq × d_model) → LayerNorm → masked multi-head attention → add → LayerNorm → feed-forward network (d → 4d → d, each token alone) → add → output of the same shape; blue residual lines carry x around each sub-layer to the add nodes. Right: the two equations h = x + MHA(LN(x)) and y = h + FFN(LN(h)); the residual stream as a running notebook each sub-layer reads a normalized copy of and adds an edit to; and the two jobs — attention moves information between positions, the FFN transforms each position independently and holds about two-thirds of the parameters.](/appendix-c/15-inside-a-transformer-block/transformer-block.png)

## Residual connections: the residual stream

A residual connection (He et al., 2015, ResNets) adds a layer's input to its output: $y = x + F(x)$. Two things follow.

**Gradients get a highway.** Differentiate:

$$
\frac{\partial y}{\partial x} = I + \frac{\partial F}{\partial x}
$$

The identity term means the gradient always has a path straight through, untouched by $F$. Across $N$ blocks, the gradient reaching the first layer includes a direct term that never shrinks — the same fix for vanishing gradients that attention gave across *time* in Chapter 11, now applied across *depth*. Without residuals, stacks beyond a dozen layers barely train; with them, 100+ layers is routine.

**Layers make edits, not rewrites.** A block that has nothing useful to contribute can output $F(x) \approx 0$ and pass its input along unchanged. A useful mental model, from interpretability research (Elhage et al., 2021), is the **residual stream**: one vector per token flowing from the embedding to the output, like a shared notebook. Every attention head and every FFN *reads* a normalized copy of the notebook and *adds* a small note back into it. Nothing overwrites the stream; everything is added.

## Layer normalization

As vectors flow through dozens of layers, their scale drifts: some dimensions blow up, others shrink, and the next layer's inputs land in ranges its weights weren't tuned for. **Normalization** rescales each vector to a standard size before each sub-layer.

**LayerNorm** (Ba, Kiros & Hinton, 2016) normalizes **each token on its own, across its $d$ features**:

$$
\mu = \frac{1}{d}\sum_{i=1}^{d} x_i, \qquad
\sigma^2 = \frac{1}{d}\sum_{i=1}^{d} (x_i - \mu)^2, \qquad
\operatorname{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta
$$

The result has mean 0 and variance 1. Then the learned per-feature scale $\gamma$ and shift $\beta$ let the model undo that where it helps. $\epsilon$ (around $10^{-5}$) avoids dividing by zero.

Why not **BatchNorm**, which revolutionised CNNs? BatchNorm averages each feature across the *batch*. That makes a token's output depend on which other sentences share its batch, on the batch size, and on padding, and at generation time there's one token at a time and no batch to average over. LayerNorm uses only the token itself, so it behaves identically in training and inference.

**RMSNorm** (Zhang & Sennrich, 2019) drops the mean subtraction and $\beta$, and only rescales by the root-mean-square:

$$
\operatorname{RMSNorm}(x) = \gamma \odot \frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}}
$$

It's cheaper and works just as well in practice, which is why Llama, Mistral, Gemma, Qwen and DeepSeek all use it.

![BatchNorm, LayerNorm, RMSNorm. Three grids of examples or tokens by features show which numbers one statistic averages over: BatchNorm averages one feature column across the batch; LayerNorm and RMSNorm average one token's row across its features. Formulas: LayerNorm γ ⊙ (x − μ)/√(σ² + ε) + β; RMSNorm γ ⊙ x/√(mean(x²) + ε). Worked example for x = [2, −1, 3, 0]: LayerNorm has μ = 1, σ² = 2.5 and gives [0.632, −1.265, 1.265, −0.632]; RMSNorm has mean(x²) = 3.5, RMS = 1.871 and gives [1.069, −0.535, 1.604, 0].](/appendix-c/15-inside-a-transformer-block/normalization-axes.png)

Worked by hand for one token $x = [2, -1, 3, 0]$ (with $\gamma = 1$, $\beta = 0$):

- LayerNorm: $\mu = 1$, $\sigma^2 = (1 + 4 + 4 + 1)/4 = 2.5$, $\sigma = 1.581$, giving $[0.632,\ -1.265,\ 1.265,\ -0.632]$.
- RMSNorm: $\tfrac{1}{4}(4 + 1 + 9 + 0) = 3.5$, RMS $= 1.871$, giving $[1.069,\ -0.535,\ 1.604,\ 0]$.

## Where the norm goes: Post-LN vs Pre-LN

The 2017 paper put LayerNorm **after** the residual addition: $y = \operatorname{LN}\big(x + F(x)\big)$. GPT-2 moved it **before** each sub-layer: $y = x + F\big(\operatorname{LN}(x)\big)$. It looks cosmetic. For deep models it isn't.

In **Post-LN**, every residual sum passes through a LayerNorm, so the clean identity path from the "highway" above is broken at every layer. Xiong et al. (2020) showed that at initialization the gradients near the output are large, and training diverges unless the learning rate is warmed up slowly from near zero. In **Pre-LN**, the path $x \to x + F(\cdot)$ is never normalized, so gradients flow straight through all $N$ blocks and training is stable even without careful warm-up. Pre-LN needs one extra LayerNorm after the last block, before the output layer.

The trade-off: in Pre-LN, the residual stream keeps growing in magnitude with depth, so late layers change it proportionally less, and a well-tuned Post-LN model can end up slightly better. Variants such as DeepNorm and "sandwich" norms try to get both. In practice nearly every large model uses Pre-LN.

![Where the LayerNorm goes: Post-LN vs Pre-LN. Left (original Transformer, BERT): x → sub-layer → add → LayerNorm → output, y = LN(x + F(x)). Right (GPT-2, GPT-3, Llama): x → LayerNorm → sub-layer → add → output, y = x + F(LN(x)), with the residual line bypassing the norm. Notes: Post-LN breaks the identity path at every layer and needs learning-rate warm-up (Xiong et al., 2020); Pre-LN keeps it clean and trains stably, with one extra LayerNorm after the last block; well-tuned Post-LN can end slightly better, and DeepNorm and sandwich norms try to get both.](/appendix-c/15-inside-a-transformer-block/pre-ln-vs-post-ln.png)

## The feed-forward network

After attention has gathered context into each token's vector, every token passes **independently** through the same small two-layer MLP:

$$
\operatorname{FFN}(x) = \operatorname{GELU}\!\left(x W_1 + b_1\right) W_2 + b_2,
\qquad W_1 \in \mathbb{R}^{d \times 4d},\ W_2 \in \mathbb{R}^{4d \times d}
$$

It expands to 4× the width (3,072 for GPT-2's 768), applies a non-linearity, and projects back. The original Transformer used ReLU. GPT-2 and BERT switched to **GELU**, $\operatorname{GELU}(x) = x\,\Phi(x)$ where $\Phi$ is the standard normal CDF. It's a smooth ReLU that lets a little negative signal through.

The FFN is the biggest part of each block: $2 \cdot d \cdot 4d = 8d^2$ weights, twice the $4d^2$ of attention. Without it, a stack of attention layers would mostly just compute weighted averages of weighted averages. The FFN is where most per-token computation — and, it turns out, much of the stored knowledge — happens. Geva et al. (2021) showed that FFN layers act like **key–value memories**: each row of $W_1$ is a key that fires on certain input patterns ("the text is about capital cities"), and the matching row of $W_2$ is a value that pushes the output toward particular tokens ("Paris"). Editing a few of those rows can change a fact the model "knows".

### SwiGLU: the modern FFN

Shazeer (2020) found that **gated** FFNs work noticeably better. SwiGLU uses three matrices: one "up" projection, one "gate" projection passed through SiLU, multiplied elementwise, then projected down:

$$
\operatorname{FFN}_{\text{SwiGLU}}(x) = \Big(\operatorname{SiLU}(x W_{\text{gate}}) \odot x W_{\text{up}}\Big) W_{\text{down}},
\qquad \operatorname{SiLU}(z) = z\,\sigma(z)
$$

The gate decides, for each hidden unit, how much of the "up" signal gets through. With three matrices instead of two, the hidden width is shrunk to $d_{\text{ff}} = \tfrac{8}{3} d$ so the parameter count stays at $3 \cdot d \cdot \tfrac{8}{3}d = 8d^2$. PaLM, Llama, Mistral and most open models use SwiGLU (Llama-3-8B rounds up to $d_{\text{ff}} = 14{,}336 = 3.5d$). Mixture-of-Experts models (Mixtral, DeepSeek-V3) replace the single FFN with many expert FFNs and route each token to a few of them.

## Counting every parameter of GPT-2 small

The model above has exactly **124,439,808** parameters. That's GPT-2 "117M" — a figure from the original paper that doesn't match the released weights. Here's where every one of them lives ($d = 768$, 12 blocks, vocabulary 50,257, context 1,024):

| part | shape | parameters |
|---|---|---|
| token embedding | 50,257 × 768 | 38,597,376 |
| position embedding | 1,024 × 768 | 786,432 |
| attention, per block | 768·2,304 + 2,304 + 768·768 + 768 | 2,362,368 |
| FFN, per block | 768·3,072 + 3,072 + 3,072·768 + 768 | 4,722,432 |
| 2 LayerNorms, per block | 2 × (768 + 768) | 3,072 |
| **one block** | | **7,087,872** |
| 12 blocks | | 85,054,464 |
| final LayerNorm | 768 + 768 | 1,536 |
| output layer | tied to token embedding | 0 |
| **total** | | **124,439,808** |

A handy rule of thumb: each block has about $4d^2$ (attention) $+ 8d^2$ (FFN) $= 12d^2$ weights, so

$$
\text{non-embedding parameters} \approx 12\, L\, d^2
$$

For GPT-2 that's $12 \times 12 \times 768^2 = 84.9\text{M}$, against the exact 85.1M; the difference is biases and LayerNorms. Training compute is roughly $6 \times \text{parameters} \times \text{tokens}$ FLOPs (Kaplan et al., 2020).

## Encoder, decoder, or both

The 2017 Transformer was a translation model with two stacks:

- The **encoder** reads the whole source sentence with **unmasked** self-attention, so every token sees every other, in both directions.
- The **decoder** writes the translation one token at a time. Each decoder block has three sub-layers: **masked** self-attention over the target written so far; **cross-attention**, where queries come from the decoder and keys and values from the encoder's output; and the FFN.

Cross-attention is Bahdanau's idea from Chapter 11 rebuilt with scaled dot products:

$$
\operatorname{CrossAttn}(Y, H) = \operatorname{softmax}\!\left(\frac{(Y W_Q)(H W_K)^{\top}}{\sqrt{d_k}}\right) H W_V
$$

where $Y$ is the decoder's states and $H$ the encoder's output.

From that design came three families:

- **Encoder-only** (BERT, RoBERTa): bidirectional, trained to fill in masked words. Excellent for classification, search and embeddings, but not built to generate.
- **Encoder–decoder** (T5, BART, Whisper): natural for input → output tasks like translation, summarization and speech-to-text.
- **Decoder-only** (GPT, Llama, Claude, Gemini): one causal stack trained to predict the next token. The simplest design, and the one that scaled. The prompt plays the role the encoder used to.

## The 2019 block vs the 2024 block

Five years of research changed surprisingly little of the skeleton — residual stream, Pre-LN, attention then FFN, stacked N times. What changed are the parts inside it. Compare GPT-2 small with Llama-3-8B:

| | GPT-2 small (2019) | Llama-3-8B (2024) | why |
|---|---|---|---|
| normalization | LayerNorm, Pre-LN | RMSNorm, Pre-LN | cheaper, same quality |
| position | learned absolute, max 1,024 | RoPE (base 500,000), 8,192 | relative, extendable (Ch. 14) |
| attention | MHA, 12 heads | GQA, 32 query / 8 KV heads | 4× smaller KV cache (Ch. 13) |
| FFN | GELU, 4d (3,072) | SwiGLU, 3.5d (14,336) | better loss per FLOP |
| biases | everywhere | none | fewer parameters, more stable |
| embeddings | tied input/output | untied | more capacity at scale |
| vocabulary | 50,257 | 128,256 | fewer tokens per text |
| size | 12 blocks, d = 768, 124M | 32 blocks, d = 4,096, 8.0B | scale |

In equations, a Llama block is

$$
h = x + \operatorname{GQA}\!\big(\operatorname{RMSNorm}(x)\big) \text{ with RoPE on } Q, K, \qquad
y = h + \operatorname{SwiGLU}\!\big(\operatorname{RMSNorm}(h)\big)
$$

Mistral, Qwen, Gemma, DeepSeek and Phi follow the same template with small twists: sliding-window attention, QK-norm, Mixture-of-Experts FFNs, or compressed KV caches.

## Quick recap

- A Transformer is one block stacked N times: $h = x + \operatorname{MHA}(\operatorname{LN}(x))$, then $y = h + \operatorname{FFN}(\operatorname{LN}(h))$.
- **Residual connections** give $\partial y/\partial x = I + \partial F/\partial x$, a gradient highway through depth. Every sub-layer reads from and adds to a shared **residual stream**.
- **LayerNorm** normalizes each token across its features; **RMSNorm** drops the mean and is the modern default. **Pre-LN** keeps the residual path clean and trains stably; Post-LN needs warm-up.
- The **FFN** ($d \to 4d \to d$, GELU) holds two-thirds of each block's weights and acts like a key–value memory. **SwiGLU** with $d_{\text{ff}} = \tfrac{8}{3}d$ is the modern version.
- GPT-2 small has exactly **124,439,808** parameters. Non-embedding parameters are $\approx 12Ld^2$.
- Encoder-only, encoder–decoder and decoder-only models all reuse this block; cross-attention connects encoder to decoder.
- The 2024 block (Llama 3) keeps the skeleton and swaps in RMSNorm, RoPE, GQA, SwiGLU and no biases.
