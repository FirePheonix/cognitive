# 12. Self-Attention and Scaled Dot-Product Attention

In Chapter 11 a decoder looked back at an encoder: one sequence attending to *another*. That's **cross-attention**. The Transformer's central move is to let a sequence attend to **itself**. Every token looks at every other token in the same sentence and asks which of them help explain it.

Take "The animal didn't cross the street because **it** was too tired." To understand *it*, you need *animal*. Change the last word to "too wide" and *it* means *street*. A static word embedding gives *it* the same vector both times. Self-attention lets *it* gather information from whichever word resolves it, so the vector that comes out depends on the sentence it's in.

This chapter builds the mechanism precisely: the query/key/value idea, the formula, a full worked example small enough to check with a pencil, why the scores are divided by $\sqrt{d_k}$, the masks, and what it costs.

---

## Queries, keys and values: a soft dictionary

A Python dictionary does a **hard lookup**. You hand it a key, and if the key matches exactly you get that one value back.

Attention does a **soft lookup**. You hand it a *query*. It compares the query with every *key*, turns the similarities into weights, and returns a weighted average of **all** the *values*. Close matches dominate; poor matches contribute almost nothing.

In self-attention all three come from the same tokens. Each token's vector $x_i$ is multiplied by three learned matrices:

$$
q_i = x_i W_Q, \qquad k_i = x_i W_K, \qquad v_i = x_i W_V
$$

- the **query** $q_i$ — what token $i$ is looking for ("I'm a pronoun; I need a noun to refer to");
- the **key** $k_i$ — what token $i$ advertises to others ("I'm a singular, animate noun");
- the **value** $v_i$ — what token $i$ actually hands over if someone attends to it.

Why three separate matrices instead of comparing the raw $x_i$ with each other? Because "what I'm looking for", "what I match on" and "what I contribute" are different questions. A verb's key might advertise "I'm the main verb" while its value carries tense and meaning. Separate projections let the model learn each role independently, and because $q_i^\top k_j \ne q_j^\top k_i$ in general, attention can be **asymmetric**: *it* can care about *animal* without *animal* caring about *it*.

## The formula

Stack the queries, keys and values of all $n$ tokens into matrices $Q, K \in \mathbb{R}^{n \times d_k}$ and $V \in \mathbb{R}^{n \times d_v}$. Scaled dot-product attention (Vaswani et al., 2017) is:

$$
\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left( \frac{Q K^{\top}}{\sqrt{d_k}} \right) V
$$

Read it right to left as four steps:

1. **Scores** $S = QK^{\top}$, an $n \times n$ grid. Entry $S_{ij} = q_i \cdot k_j$ says how well token $i$'s query matches token $j$'s key.
2. **Scale**: divide every score by $\sqrt{d_k}$.
3. **Softmax each row**, so row $i$ becomes a probability distribution $A_{i,:}$ over all tokens.
4. **Mix values**: $O = AV$. Row $i$ of the output is $o_i = \sum_j A_{ij}\, v_j$.

The output has one row per token, the same as the input — attention replaces each token's vector with a context-aware blend, which is what lets layers stack.

### Worked example: "the cat sat", by hand

To make every number checkable, take $d_k = 4$ and small integer Q, K, V (in a real model these come from the projections above):

$$
Q = \begin{bmatrix} 1&0&1&0 \\ 0&2&1&0 \\ 1&1&0&2 \end{bmatrix}, \quad
K = \begin{bmatrix} 2&0&0&0 \\ 0&1&2&0 \\ 1&0&0&1 \end{bmatrix}, \quad
V = \begin{bmatrix} 1&0&0&1 \\ 0&2&0&0 \\ 0&0&3&1 \end{bmatrix}
$$

Rows are *the*, *cat*, *sat*.

**Step 1 — scores.** Each entry is one dot product. For example, *cat*'s query against *cat*'s key is $0\cdot0 + 2\cdot1 + 1\cdot2 + 0\cdot0 = 4$.

$$
S = QK^{\top} = \begin{bmatrix} 2&2&1 \\ 0&4&0 \\ 2&1&3 \end{bmatrix}
$$

**Step 2 — scale** by $\sqrt{4} = 2$: rows become $[1, 1, 0.5]$, $[0, 2, 0]$, $[1, 0.5, 1.5]$.

**Step 3 — softmax each row.** For *cat*: $e^0 = 1$, $e^2 = 7.389$, $e^0 = 1$, total 9.389, so the weights are $[0.107,\ 0.787,\ 0.107]$. Doing all three rows:

| query ↓ / key → | the | cat | sat |
|---|---|---|---|
| the | 0.384 | 0.384 | 0.233 |
| cat | 0.107 | **0.787** | 0.107 |
| sat | 0.307 | 0.186 | **0.506** |

**Step 4 — mix the values.** *cat*'s output is $0.107\,v_{\text{the}} + 0.787\,v_{\text{cat}} + 0.107\,v_{\text{sat}}$:

$$
o_{\text{cat}} = 0.107\,[1,0,0,1] + 0.787\,[0,2,0,0] + 0.107\,[0,0,3,1] = [0.107,\ 1.574,\ 0.320,\ 0.213]
$$

Mostly its own value, with a little of each neighbour mixed in.

## Why divide by √d_k?

The division looks like a fudge factor. It's actually a one-line variance calculation.

Suppose the components of a query and a key are independent, with mean 0 and variance 1 — roughly what you get at initialization. Each product $q_i k_i$ then has mean 0 and variance $\mathbb{E}[q_i^2]\,\mathbb{E}[k_i^2] = 1$. A dot product adds up $d_k$ of these independent terms, and variances of independent terms add:

$$
\operatorname{Var}\!\left(q^{\top} k\right) = \sum_{i=1}^{d_k} \operatorname{Var}(q_i k_i) = d_k
\qquad\Longrightarrow\qquad
\operatorname{std}\!\left(q^{\top} k\right) = \sqrt{d_k}
$$

With $d_k = 64$ (the original Transformer) typical scores are around ±8; at $d_k = 128$ (most modern LLMs) they're around ±11. Dividing by $\sqrt{d_k}$ puts them back near ±1, whatever the head size.

### Why large scores are a problem: the softmax gradient

The soft-lookup demo showed that big scores make the softmax nearly one-hot. That isn't just "too confident" — it stops learning. The derivative of softmax output $\alpha_i$ with respect to score $s_j$ is

$$
\frac{\partial \alpha_i}{\partial s_j} = \alpha_i\left(\delta_{ij} - \alpha_j\right)
$$

where $\delta_{ij}$ is 1 if $i = j$ and 0 otherwise. If one weight is ≈ 1 and the rest are ≈ 0, every entry is ≈ 0: for the winner $\alpha(1-\alpha) \approx 0$, and for the others $\alpha_i \approx 0$. A saturated softmax passes almost no gradient back to the queries and keys, so they can't learn to attend anywhere else.

Vaswani et al. said exactly this: additive attention beat unscaled dot-product attention at large $d_k$, and they suspected "the dot products grow large in magnitude, pushing the softmax function into regions where it has extremely small gradients."

## Masks: what a token is allowed to see

Attention lets every token see every other token. Often that's wrong, and we fix it by adding a **mask** $M$ to the scores before the softmax:

$$
A = \operatorname{softmax}\!\left( \frac{QK^{\top}}{\sqrt{d_k}} + M \right),
\qquad
M_{ij} = \begin{cases} 0 & \text{if token } i \text{ may see token } j \\ -\infty & \text{otherwise} \end{cases}
$$

Since $e^{-\infty} = 0$, blocked positions get exactly zero weight and pass no gradient. There are two common masks.

**Causal mask (decoders).** A language model is trained to predict token $t+1$ from tokens $1 \dots t$. If position $t$ could attend to $t+1$, it would just copy the answer. So token $i$ may only see $j \le i$, and the allowed pattern is lower-triangular. This is what lets a GPT train on **every position of a sequence in parallel** — one forward pass gives $n$ next-token predictions, each using only its own past — while generating one token at a time behaves identically.

**Padding mask (batches).** Sentences in a batch have different lengths, so short ones are padded. Padding tokens are not real words, so no query may attend to them: the mask blocks every *key* column that is padding. Decoders apply both masks together.

Encoders like BERT use no causal mask — every token sees the whole sentence in both directions — but still use padding masks.

## What it costs, and FlashAttention

For a sequence of $n$ tokens with head size $d$:

- computing $QK^{\top}$ takes $n^2 d$ multiply-adds, and so does $AV$ — **quadratic in sequence length**;
- the score matrix itself has $n^2$ entries per head.

Doubling the context quadruples the attention work. At $n = 8{,}192$ the score matrix is 67 million numbers *per head*: 128 MiB in 16-bit floats, or 4 GiB for the 32 heads of one layer — just for an intermediate result that is used once and thrown away.

The cost isn't only arithmetic. A GPU has a small amount of very fast on-chip memory (SRAM) and a large amount of slower main memory (HBM). A naive implementation writes the full $n \times n$ matrix to HBM, reads it back for the softmax, writes it again and reads it again for $AV$. For long sequences, that memory traffic — not the multiplications — is the bottleneck.

**FlashAttention** (Dao et al., 2022) computes exactly the same result without ever building the full matrix. It splits Q, K and V into tiles that fit in SRAM, and computes the softmax **incrementally** — the "online softmax" trick: keep a running maximum and a running sum for each row, and rescale the partial output whenever a new tile raises the maximum. Memory drops from $O(n^2)$ to $O(n)$, and it runs 2–4× faster despite doing *more* arithmetic, because it moves far less data. FlashAttention-2 (2023) and -3 (2024) refined the work partitioning for newer GPUs. It's now the default: `F.scaled_dot_product_attention` uses it automatically when it can.

### A preview: the KV cache

When a trained decoder generates text, each new token needs only **one new query**, but it attends over the keys and values of every previous token. Those don't change once computed, so inference engines store them in a **KV cache** instead of recomputing them. Its size grows with context length and becomes the main memory cost of serving long contexts — which is why Chapter 13 introduces ways to share keys and values between heads.

## What self-attention actually computes

### Contextual embeddings

Before attention, *bank* has one vector, whether it's a river bank or a savings bank. After a few attention layers, the *bank* in "she sat on the river bank" has absorbed information from *river* and *sat*, and the *bank* in "the bank approved the loan" has absorbed *approved* and *loan*. The two vectors move to different regions of the space. That is the difference between static embeddings (Word2Vec, GloVe) and contextual ones, and it's why the same word can mean different things to a Transformer.

![From dictionary meaning to contextual meaning. A 2-D sketch: the static embedding of "bank" sits between a finance cluster (deposit, money, loan, cash) and a river cluster (river, water, shore, fish). In "I deposited the cash at the bank" attention pulls it to bank₁ in the finance cluster; in "We sat on the river bank, watching the water" it moves to bank₂ in the river cluster. A side panel gives the update for one layer, x′_i = x_i + Σ_j α_ij W_O v_j: the residual keeps the original meaning and attention adds a context-dependent correction.](/appendix-c/12-self-attention-and-scaled-dot-product/contextual-embeddings.png)

### A learned kernel smoother

There's a useful statistical way to see the formula. Classic **kernel regression** (Nadaraya–Watson, 1964) predicts a value at a point by averaging known values, weighted by how similar their positions are:

$$
\hat{y}(x) = \sum_j \frac{K(x, x_j)}{\sum_k K(x, x_k)}\, y_j
$$

Attention is exactly this, with the similarity kernel $K(q, k) = \exp\!\left(q^{\top} k / \sqrt{d_k}\right)$, and with queries, keys and values all **learned** projections. Each layer is a smoother whose notion of "similar" is trained for the task.

### Self-attention vs cross-attention

| | where Q comes from | where K and V come from | used in |
|---|---|---|---|
| self-attention | the sequence itself | the same sequence | every Transformer layer |
| masked (causal) self-attention | the sequence itself | the same sequence, past only | GPT-style decoders |
| cross-attention | the decoder | the encoder's output | translation, T5, Whisper; Bahdanau (Ch. 11) |

The mathematics is identical in all three; only where the matrices come from changes.

## Quick recap

- **Self-attention** lets every token gather information from every other token in the same sequence, turning static embeddings into contextual ones.
- Each token is projected into a **query**, a **key** and a **value**; attention is a *soft* dictionary lookup that returns a similarity-weighted average of values.
- $\operatorname{Attention}(Q,K,V) = \operatorname{softmax}(QK^{\top}/\sqrt{d_k})\,V$: scores, scale, row-wise softmax, mix.
- The $\sqrt{d_k}$ comes from $\operatorname{Var}(q^{\top}k) = d_k$. Without it, scores grow with head size, the softmax saturates, and its gradient $\alpha_i(\delta_{ij} - \alpha_j)$ vanishes.
- **Masks** add $-\infty$ to forbidden scores: causal masks for decoders (and parallel training), padding masks for batches.
- Cost is $O(n^2 d)$ time and $O(n^2)$ memory per head. **FlashAttention** computes the same thing in $O(n)$ memory by tiling and an online softmax; the **KV cache** stores past keys and values during generation.
