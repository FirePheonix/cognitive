# 7. How Neural Networks Learn

At the end of Appendix A, you had embedding vectors. A sentence like "The cat sat" became a `(3, 768)` tensor — three rows of 768 numbers each. The question left hanging was: what do you *do* with that?

The answer is: you feed it through a neural network. The network transforms those vectors through a series of learned operations, eventually producing a prediction — which word comes next, which class this belongs to, whatever the task requires. Then you check how wrong it was. Then you adjust every number in the network, very slightly, in the direction that would have made it less wrong. Then you repeat this billions of times.

That's the whole thing. Let's make it concrete.

---

## What Is a Neuron?

A neuron is the smallest unit of computation in a neural network. It takes some numbers in, does a calculation, and produces one number out.

Specifically: it takes a list of inputs, multiplies each one by a learnable weight, adds them all up, adds a bias term, and then passes the result through an activation function. In code:

```
output = activation(w₁x₁ + w₂x₂ + w₃x₃ + ... + wₙxₙ + b)
```

That's the whole neuron. `w₁, w₂, ... wₙ` are weights — numbers the network learns. `b` is a bias — also learned. `x₁ ... xₙ` are inputs. The activation function (ReLU, GELU, sigmoid...) introduces non-linearity so that stacking neurons actually accomplishes something more than a single linear operation would.

![Neuron structure and activation functions — inputs × weights, sum with bias, activation, output; ReLU, GELU, and Sigmoid compared](/appendix-b/07-how-neural-networks-learn/neurons-and-functions.png)

A network is just thousands or millions of these neurons arranged in layers, all connected, all learning their weights simultaneously.

## The Math, Drawn Out

Before stacking neurons into layers, see the numbers move — not as abstract symbols but as actual grids.

![One neuron computes one number (top) and a layer is many neurons in parallel via matrix multiply (bottom)](/appendix-b/07-how-neural-networks-learn/neuron-and-layer-diagram.png)

The single line `Z = X @ W + b` computes all neurons × all tokens in one GPU operation. One neuron, one number out. A layer, many numbers out simultaneously.

### Shapes change as you stack layers

![Shapes change as you stack layers — input X(2,3) flows through linear layers changing feature dimensions, and in a real LLM (batch, seq_len, 768) flows through transformer blocks to final logits (batch, seq_len, 50257)](/appendix-b/07-how-neural-networks-learn/shapes-stacking-layers.png)

The batch dimension (rows) never changes — all tokens are always processed in parallel. Only the feature dimension (cols) changes, controlled by each weight matrix's shape.

## From One Neuron to a Layer

One neuron produces one number. A layer is just many neurons operating on the same input in parallel — producing many numbers at once. And because each neuron is doing `w · x + b`, running a full layer is equivalent to a single matrix multiplication: `output = activation(X @ W + b)`.

That's the key insight from Chapter 6. The "computation of a layer" and "a matrix multiply followed by an activation" are the same thing. All the neurons in a layer fire simultaneously; their weights live in the rows of `W`.

## Building a Multi-Layer Network

Stack several layers and you have a deep neural network. Each layer transforms the representation produced by the previous one. Early layers tend to detect simple patterns; later layers combine those into more complex abstractions. The "depth" is what gives deep learning its power.

## The Forward Pass

When data flows from the input through every layer to the output, that's called the **forward pass**. Data goes in, math happens, predictions come out.

## Loss: Quantifying "How Wrong"

After the forward pass, you need a single number that captures how wrong the prediction was. That's the **loss** (also called the cost or objective function). The training process is, mechanically, the process of minimizing the loss.

For classification tasks — which includes next-token prediction in language models — the standard loss is **cross-entropy**. It measures how much probability the model assigned to the correct answer. If the model said "there's a 90% chance the next word is 'cat'" and "cat" really was next: low loss. If it said "there's a 0.01% chance" and "cat" was next: very high loss.

## Backpropagation: Tracing the Blame

You have a loss. Now you need to figure out: which weights caused it? And in which direction should each weight move to reduce it?

The answer is **backpropagation** — an algorithm that applies the chain rule of calculus backwards through the network. It computes the gradient of the loss with respect to every single weight. The gradient tells you: "if you increase this weight slightly, does the loss go up or down?"

The math is deep but the implementation isn't. PyTorch does it automatically. You call `loss.backward()` and every parameter's `.grad` attribute gets filled in.

**What the chain rule actually does:** The loss is a function of the output layer. The output layer is a function of the hidden layers. The hidden layers are functions of the input and the weights. The chain rule lets you trace backwards: "how does a tiny change in this weight, all the way back in layer 1, propagate forward through the network and eventually affect the loss?"

The answer is a product of partial derivatives, computed layer by layer from the output back to the input. PyTorch's autograd engine builds a computation graph during the forward pass and then walks it backwards.

## Gradient Descent: Actually Moving the Weights

You have gradients. Now you adjust the weights:

```
weight_new = weight_old - learning_rate × gradient
```

That's gradient descent. Subtract the gradient multiplied by a small number (the learning rate). The gradient points toward higher loss — so subtracting it points toward lower loss.

The **learning rate** is a small constant, typically somewhere between `0.0001` and `0.01`. Too big and the weight updates overshoot — the model oscillates instead of converging. Too small and training takes forever.

The four-line sequence — `zero_grad()`, forward pass, `backward()`, `optimizer.step()` — is the heartbeat of all neural network training. It repeats millions or billions of times. Every repetition nudges the weights a tiny bit toward making better predictions. That's how a random initialization turns into a model that can write essays.

## The Full Training Loop

In practice you don't train on one example at a time. You take a **batch** — typically 16 to 512 examples — compute the average loss across all of them, and update the weights once. This is **mini-batch gradient descent**. It's more stable than updating on one example at a time (stochastic gradient descent) and more computationally efficient than the full dataset (batch gradient descent).

The complete training loop also evaluates on a validation set periodically to check whether the model is genuinely learning or just memorizing the training data.

## The Vanishing Gradient Problem

There's a wrinkle. Backpropagation multiplies gradients through every layer in the network — from the output back to the input. If those multiplications consistently produce numbers smaller than 1 (which they often do when using tanh or sigmoid activations), the gradients shrink exponentially as they travel backward.

By the time the gradient reaches the first few layers of a deep network, it can be so small it's practically zero. Those early layers barely update at all. The network effectively stops learning its early representations.

```text
Vanishing gradient — WITHOUT residual connections (tanh network, 8 layers):

  Loss                                              gradient
   |                                                  |
   ↓  Layer 8  grad ≈ 0.039  ████████████████████████|
   ↓  Layer 7  grad ≈ 0.013  ████████                |
   ↓  Layer 6  grad ≈ 0.004  ███                     |
   ↓  Layer 5  grad ≈ 0.001  █                       |
   ↓  Layer 4  grad ≈ 0.0001 █                       |
   ↓  Layer 3  grad ≈ 0.00002 (nearly 0)             |
   ↓  Layer 2  grad ≈ 0.000003 (frozen)              |
   ↓  Layer 1  grad ≈ 0.0000004 (dead)               |

  WITH residuals (x = x + layer(x)):

  All layers   grad ≈ 0.030  ████████████████████████  (uniform!)

  Residual path: grad flows ADDITIVELY through the skip connection,
  bypassing the multiplicative shrinkage at each layer.
```

This is the **vanishing gradient problem**, and it turns out to be important far beyond just deep feed-forward networks — it's the exact same mechanism that breaks RNNs on long sequences, which is what the next two chapters are about.

## Quick Recap

- A **neuron** multiplies inputs by weights, adds a bias, and passes through an activation: `output = activation(w · x + b)`.
- A **layer** is many neurons operating on the same input in parallel — equivalent to a matrix multiply plus activation.
- The **forward pass** is data flowing through the network to produce a prediction.
- The **loss** (usually cross-entropy for classification/language modeling) measures how wrong the prediction was.
- **Backpropagation** uses the chain rule to compute the gradient of the loss with respect to every weight in the network.
- **Gradient descent** updates each weight by `w = w - lr × gradient`, moving the weights toward lower loss.
- The **training loop** repeats forward → loss → backward → update on batches of data, typically for millions of iterations.
- The **vanishing gradient problem** occurs when gradients shrink exponentially as they travel backward through deep networks. **Residual connections** (`x = x + layer(x)`) solve it.

With this foundation in place, the next question is whether a network built from these principles can understand language. The answer is: not with a plain feed-forward architecture. The problem is deeper than it looks.

### The Math Behind the Learning: Backpropagation Unpacked

A neural network learns by measuring how wrong it is (the loss), then working backwards through every operation to figure out how each weight contributed to that wrongness. This process is **backpropagation** — just the chain rule from calculus, applied systematically.

**Forward pass — building the computation graph:**
For a two-layer network:
$$z_1 = W_1 x + b_1, \quad h = \phi(z_1), \quad z_2 = W_2 h + b_2$$
$$\hat{y} = \text{softmax}(z_2), \quad \mathcal{L} = -\log \hat{y}_y$$

Each arrow in this computation stores a local derivative. Backprop uses the chain rule to combine them:
$$\frac{\partial z}{\partial x} = \frac{\partial z}{\partial y} \cdot \frac{\partial y}{\partial x}$$

**Gradients through a linear layer:**
For $z = Wx + b$, if you know the upstream gradient $\delta_z = \partial \mathcal{L} / \partial z$, then:
$$\frac{\partial \mathcal{L}}{\partial W} = \delta_z x^\top \quad \text{(outer product)}$$
$$\frac{\partial \mathcal{L}}{\partial b} = \delta_z$$
$$\frac{\partial \mathcal{L}}{\partial x} = W^\top \delta_z \quad \text{(the gradient that flows to the previous layer)}$$
Intuition: $\delta_z x^\top$ is "how much does each weight matter?" — it's the upstream error scaled by the input that produced it.

**Activation function derivatives — why they matter:**
$$\sigma'(x) = \sigma(x)(1 - \sigma(x)) \quad \text{(sigmoid — saturates near 0 and 1)}$$
$$\tanh'(x) = 1 - \tanh^2(x) \quad \text{(tanh — also saturates)}$$
$$\text{ReLU}'(x) = \mathbf{1}[x > 0] \quad \text{(binary, doesn't saturate)}$$
Modern transformers use GELU — smooth, doesn't hard-zero negatives like ReLU.

**The beautiful result: Softmax + Cross-Entropy gradient:**
When you combine softmax with cross-entropy loss, the gradient simplifies to something elegant:
$$\boxed{\frac{\partial \mathcal{L}}{\partial z} = p - y}$$
"Predicted probabilities minus true labels." The gradient is largest where the model is most wrong, and zero where it's exactly right. This is why neural networks converge — the gradient naturally focuses effort on mistakes.

**Debugging checklist — things to check before assuming the model is broken:**
1. Can the model overfit a tiny dataset (10 examples)? If not, the architecture is broken.
2. Is the initial loss at the right value? (For 10-class classification: $\log(10) \approx 2.3$)
3. Do gradients flow? Check gradient norms — zero means vanishing gradients, infinity means exploding.
4. Are parameters actually updating? Print weights before and after one step.
5. Are your padding/mask operations correct?
6. Is the model in `train` mode (not `eval`) during training?
