# 9. RNNs, LSTMs, and Why They Weren't Enough

Chapter 8 ended with the right question: how do you build a network that reads text in order, shares weights across positions, and maintains memory across arbitrary sequence lengths?

The answer — for about a decade — was the Recurrent Neural Network. And then its refined successor, the Long Short-Term Memory network. These architectures dominated NLP from the early 2010s through 2017. Translation, text classification, speech recognition, language generation — all of it ran on LSTMs.

Then they got replaced. Completely. Within two years of the transformer paper, almost nobody was training new RNN models for language.

To understand why, you need to understand what RNNs actually do, why they work at all, and why they break in specific ways that ultimately couldn't be patched.

---

## The RNN: A Loop in Time

A recurrent neural network has one structural difference from a feed-forward network: it has a feedback loop. The output of the network at time step `t` gets fed back in as an input at time step `t+1`.

More precisely, the RNN maintains a **hidden state** `h` — a vector — that gets updated at every step. At each step, the hidden state is computed from the current input token *and* the previous hidden state:

```
h_t = tanh(W_h · h_{t-1} + W_x · x_t + b)
```

```text
RNN unrolled across time — same weights W_h, W_x at every step:

  x₁       x₂       x₃       x₄       x₅       x₆
  │        │        │        │        │        │
  ↓        ↓        ↓        ↓        ↓        ↓
h₀ →[RNN]→h₁→[RNN]→h₂→[RNN]→h₃→[RNN]→h₄→[RNN]→h₅→[RNN]→h₆
           │        │        │        │        │        │
           ↓        ↓        ↓        ↓        ↓        ↓
          (y₁)     (y₂)     (y₃)     (y₄)     (y₅)    y₆

  h_t = tanh( W_h · h_{t-1}  +  W_x · x_t  +  b )
                  ↑ "memory"       ↑ new input

  Each [RNN] box uses THE SAME W_h and W_x — weight sharing over time.
  h₆ is a compressed summary of the entire 6-token sequence.
```

![The RNN: A Loop in Time — RNN unrolled across 6 time steps showing weight sharing, the recurrence equation h_t = tanh(W_h · h_{t-1} + W_x · x_t + b), typical shapes, and a single RNN cell zoomed in](/appendix-b/09-rnns-lstms-and-the-limits-of-recurrence/rnn-unrolled-loop.png)

Where:
- `x_t` is the embedding of the current token
- `h_{t-1}` is the hidden state from the previous step (the "memory")
- `W_h` and `W_x` are learnable weight matrices — the same at every step
- `tanh` squashes the output to [-1, 1]

The output at each step can be used to make a prediction (next-word prediction, sentiment, etc.) or just passed to the next step.

## Why the Same Weights at Every Step Is So Powerful

The key property of the RNN formula is that `W_h`, `W_x`, and `b` are the same at every time step. The network applies the same transformation over and over, on inputs of varying lengths.

This is **weight sharing over time**, and it solves both problems from Chapter 8 in one move:

- **Variable length**: you just keep applying the same weights until the sequence ends. A 6-token sentence uses the formula 6 times. A 600-token document uses it 600 times. Same weights either way.
- **Weight sharing**: the network learns "what words mean" once, and applies that knowledge everywhere in the sequence. "cat" at position 1 and "cat" at position 47 both go through the same `W_x` — so the model has consistent representations.

## The Vanishing Gradient Problem, Again

Remember the vanishing gradient problem from Chapter 7? When gradients travel backward through many layers, they can shrink to near-zero — leaving the early layers essentially untrained.

An RNN has the same problem, just in the time dimension instead of the layer dimension.

When you backpropagate through an RNN, you backpropagate through every time step. The gradient travels backward from the loss at step `t=100` all the way back to step `t=1`. At each step, it gets multiplied by the weight matrix `W_h` and the derivative of `tanh`. If those numbers are even slightly less than 1, the product across 100 steps shrinks to nearly zero.

```text
Gradient decay over time steps (backprop from t=60 backward):

  RNN  ← each step multiplies by tanh'(z) × W_h  (often < 1)

  t=60 ████████████████████████  grad ≈ 7.7e-2
  t=50 ███████████████           grad ≈ 3.9e-2
  t=40 █████████                 grad ≈ 2.2e-3
  t=30 ████                      grad ≈ 9.5e-5
  t=20 █                         grad ≈ 8.7e-8
  t=10 █                         grad ≈ 4.2e-12
  t=1  █                         grad ≈ 3.1e-17  ← effectively 0

  LSTM  ← additive cell state creates a "gradient highway"

  t=60 ████  grad ≈ 7.7e-2
  t=50 ████  grad ≈ 5.3e-4  (much flatter decay)
  t=40 ████  grad ≈ 4.1e-4
  t=30 ████  grad ≈ 3.4e-4
  t=20 ████  grad ≈ 2.9e-4
  t=10 ████  grad ≈ 3.2e-4
  t=1  ████  grad ≈ 4.8e-4  ← still alive

  Ratio at t=1: LSTM is ~10¹³× larger than RNN
```

This is called **Backpropagation Through Time (BPTT)**, and the vanishing gradient it produces means the model can only "remember" the last few tokens well. Information from 50 or 100 steps back might as well not exist.

Every time the sequence doubles in length, the gradient ratio roughly squares. At 100 tokens, position 1 gets essentially zero gradient. The model can't learn from anything that happened more than about 20–30 steps ago.

This was a well-known and well-documented problem by the early 1990s. Hochreiter analyzed it mathematically in 1991. Bengio et al. showed in 1994 that it was a fundamental difficulty, not just a training issue. The field knew RNNs were broken for long sequences. What took until 1997 to solve was finding an architecture that could actually keep gradients alive over long spans.

## LSTMs: Gated Memory

The Long Short-Term Memory network was proposed by Sepp Hochreiter and Jürgen Schmidhuber in 1997. It's the result of asking: what if instead of a single hidden state, we had a separate **cell state** that was designed to preserve gradients over long time spans?

The key insight is that the problem with vanilla RNNs is *multiplicative* — gradients shrink because they're repeatedly *multiplied* by numbers less than 1. The LSTM's cell state uses *additive* updates instead. Addition doesn't shrink gradients the way multiplication does. Information can flow relatively unchanged across hundreds of steps.

But you can't just add everything — you'd accumulate garbage indefinitely. So the LSTM uses **gates** — learned sigmoid functions that act like valves, controlling how much of the new information enters the cell state and how much of the old information remains.

![LSTMs: Gated Memory — LSTM cell with forget gate, input gate, candidate, and output gate; cell state updated additively (c_t = f_t * c_{t-1} + i_t * g_t); full equations and key idea that additive updates preserve gradients over long time spans](/appendix-b/09-rnns-lstms-and-the-limits-of-recurrence/lstm-gated-memory.png)

```text
LSTM cell — one time step:

  h_{t-1} ──────────────────────────────────────────────────────┐
  x_t ──────────────────────────────────────────────────────┐   │
                                                             │   │
  combined = [h_{t-1}, x_t]                                 │   │
      │                                                      │   │
      ├──→ forget gate  f_t = sigmoid(W_f · combined)  ─→ × c_{t-1}
      │         ↑ "how much old cell state to keep?"        │
      │                                                      ↓
      ├──→ input gate   i_t = sigmoid(W_i · combined)  ─→ × g_t ──→ + ──→ c_t
      │                                                               ↑
      ├──→ candidate    g_t = tanh(W_c · combined)  ─────────────────┘
      │         ↑ "what new information to add?"
      │
      └──→ output gate  o_t = sigmoid(W_o · combined)
                ↑ "what part of cell state to expose?"
                              │
                c_t ──tanh──→ × ──→ h_t  (new hidden state)

  KEY: c_t = f_t ⊙ c_{t-1}  +  i_t ⊙ g_t
       Additive update ──→ gradients flow without shrinking!
```

The three gates in plain language:

- **Forget gate** `f_t`: how much of the *old* cell state to keep. Near 1 = remember, near 0 = forget. The model learns *when* to reset. If you're processing "I grew up in France" and then hit "so I speak...", the forget gate can learn to keep "France" in the cell state even though many other tokens have passed.

- **Input gate** `i_t`: how much of the *new candidate information* to add. Not everything worth knowing from the current token should necessarily update the cell state.

- **Output gate** `o_t`: what part of the cell state to expose as the hidden state at this step. The cell state is internal memory; the hidden state is what gets passed to other components.

## Why LSTMs Have Better Gradient Flow

The key equation is the cell state update:

```
c_t = f_t ⊙ c_{t-1}  +  i_t ⊙ g_t
```

That `⊙` is element-wise multiplication. The important thing is that `c_{t-1}` flows into `c_t` through **addition** — specifically, `f_t * c_{t-1}` plus a new term. During backpropagation, the gradient of the loss with respect to `c_{t-1}` flows back through this addition relatively cleanly.

In a vanilla RNN, the gradient path is multiplicative all the way — every step multiplies by `tanh'(z) * W_h`, and if that product is consistently < 1, gradients vanish. In an LSTM, the path through the cell state is additive plus a multiplicative `f_t` factor. If the forget gate learns to stay near 1 for important information, the gradient can traverse hundreds of steps without shrinking to zero.

Around 2014, Kyunghyun Cho and collaborators introduced the **Gated Recurrent Unit (GRU)**. The GRU simplifies the LSTM by combining the forget and input gates into a single "update gate" and eliminating the separate cell state.

## What RNNs and LSTMs Got Right

Before getting to the limitations, it's worth being concrete about what these architectures *could* do. By 2016, LSTM-based systems were:

- **Translating between languages** with near-human accuracy on many language pairs (Google's production translation system ran on LSTMs until 2017)
- **Generating plausible text** — Karpathy's famous "The Unreasonable Effectiveness of RNNs" showed that an LSTM trained on Shakespeare could produce Shakespearean-sounding text, trained on Linux kernel code could produce vaguely compilable C
- **Doing speech recognition** with error rates approaching human performance
- **Summarizing documents** and **answering questions**

This was genuinely impressive. The NLP world in 2014–2016 felt like rapid progress.

## The Three Problems That Wouldn't Go Away

Despite the real progress, three fundamental problems with LSTMs resisted every attempt to fix them:

### Problem 1: Sequential Computation

An RNN or LSTM processes tokens one at a time, in order. You cannot compute step `t+1` until step `t` is done. This is inherently sequential — it cannot be parallelized across tokens.

## The Architectural Dead End

By 2016–2017, the NLP community was staring at a set of constraints that felt hard to escape:

| Constraint | Why It Matters |
|:-----------|:---------------|
| Sequential computation | Can't parallelize training → slow → can't scale |
| Fixed-size hidden state | Compresses everything through a bottleneck |
| Gradient decay over distance | Long-range dependencies still difficult |
| Recurrent structure | Makes batching and hardware utilization awkward |

People tried many things. Stacking more LSTM layers. Bidirectional LSTMs (processing sequences forward and backward simultaneously). Better optimization algorithms. Attention bolted on as a supplementary mechanism. Each iteration improved results somewhat, but the fundamental constraints remained.

The problem wasn't the training algorithm or the depth or the learning rate — it was the *recurrence itself*. As long as information had to pass through a fixed-size bottleneck one step at a time, you were bounded.

What was needed wasn't a better RNN. It was a completely different way to handle sequence context — one that processed all positions simultaneously and let every position directly access every other position with no bottleneck in between.

## The Attention Preview: How the Problem Gets Solved

The attention mechanism that eventually replaced recurrence is actually not complicated once you understand what problem it's solving. The constraints were:

1. No more bottleneck — don't compress all history into a fixed vector
2. No more sequential dependency — let all positions compute in parallel
3. Long-range connections — let position 1 talk directly to position 100

The solution: at each step, instead of having a hidden state that summarizes everything that came before, let the model *directly query* all previous positions. Let it learn which positions are relevant to the current prediction and weight them accordingly.

No recurrence. No hidden state. Just learned weighted connections between positions.

That's attention. And when you build an entire language model out of it — stacking layers of attention over large batches of data — the results were dramatically better than anything LSTMs had achieved, and orders of magnitude faster to train.

Appendix C covers how attention works and how the Transformer is built from it. Everything in this appendix was the necessary prerequisite: you needed to understand what problem existed before the solution makes sense.

## Quick Recap

- An **RNN** processes tokens one at a time, maintaining a hidden state `h_t = tanh(W_h * h_{t-1} + W_x * x_t + b)`. The same weights at every step handle variable-length sequences.
- **Backpropagation Through Time (BPTT)** computes gradients by unrolling the RNN and propagating backward through every time step — which causes gradients to vanish exponentially, making long sequences hard to learn.
- An **LSTM** adds a separate **cell state** with additive updates (`c_t = f_t * c_{t-1} + i_t * g_t`), plus three gates (forget, input, output) that learn to control information flow. This significantly improves gradient flow over long sequences.
- A **GRU** simplifies the LSTM to two gates (update and reset), achieving similar performance with fewer parameters.
- Despite major improvements over RNNs, LSTMs still have three fundamental problems: **sequential computation** (can't parallelize), **information bottleneck** (fixed-size hidden state), and **practical context limits** (~100–200 tokens).
- The solution — attention — lets every position directly attend to every other position without going through a sequential bottleneck. That story is in Appendix C.

### The Mathematics of Sequence Memory: LSTM Gate Equations

**The language modeling objective:** RNNs are trained to predict the next token:
$$P(x_{t+1} \mid x_{\le t})$$
Over an entire sequence, the training loss is:
$$\mathcal{L} = -\sum_{t=1}^{T} \log P_\theta(x_t \mid x_{<t})$$
This is exactly the same objective used by GPT-4 — RNNs were training on the same task, just with a weaker architecture.

**Perplexity — the measurement unit of language models:**
Perplexity converts the loss into a more interpretable number — roughly "how many words is the model equally likely to choose from at each step?":
$$\text{PPL} = \exp\left(-\frac{1}{T}\sum_t \log P(x_t \mid x_{<t})\right)$$
A perplexity of 10 means the model is, on average, as confused as if it were choosing uniformly from 10 options. Lower is better. GPT-3 achieves PPL ~20 on some benchmarks; humans are ~15.

> **Important:** Perplexity can't be compared across models with different tokenizers. A model that splits words into more tokens will have numerically different (often lower) perplexity for reasons unrelated to actual language understanding.

**Why gradients die over long sequences — the math:**
When you backpropagate through an RNN unrolled over $T$ steps, the gradient at step $k$ depends on a chain of matrix products:
$$\frac{\partial h_t}{\partial h_k} = \prod_{i=k+1}^{t} \frac{\partial h_i}{\partial h_{i-1}}$$
If the spectral radius of each Jacobian is less than 1, this product shrinks exponentially toward zero — the vanishing gradient problem. If greater than 1, it grows exponentially — the exploding gradient problem. You can't reliably learn dependencies spanning more than ~20-30 steps.

**Gradient clipping — the cheap fix for exploding gradients:**
$$g \leftarrow g \cdot \min\left(1, \frac{\tau}{\|g\|}\right)$$
If the gradient norm exceeds threshold $\tau$, scale it down proportionally. This prevents the optimizer from taking catastrophically large steps when gradients explode. It doesn't fix vanishing gradients.

**LSTM gate equations — how memory works:**
The LSTM maintains two states: $h_t$ (hidden state, like RNN) and $c_t$ (cell state, the long-term memory). Four gates control information flow:

Forget gate — what fraction of old memory to keep:
$$f_t = \sigma(W_f[x_t, h_{t-1}] + b_f)$$

Input gate — what new information to write:
$$i_t = \sigma(W_i[x_t, h_{t-1}] + b_i)$$

Candidate memory — what the new information is:
$$\tilde{c}_t = \tanh(W_c[x_t, h_{t-1}] + b_c)$$

Cell state update — the additive mechanism that preserves gradients:
$$c_t = f_t \odot c_{t-1} + i_t \odot \tilde{c}_t$$

Output — what to expose from cell state:
$$h_t = o_t \odot \tanh(c_t)$$

The critical insight is the **additive** update to $c_t$. Because the cell state is updated by addition (not multiplication), gradients can flow back through time without shrinking. The forget gate $f_t$ can stay near 1 for many steps, letting the model remember things from far back.

**Exposure bias — the train-test mismatch:**
During training, the RNN sees the *true* previous token:
$$x_t^{\text{in}} = x_t^{\text{gold}}$$
During inference, it sees its *own previous prediction*:
$$x_t^{\text{in}} = \hat{x}_t$$
This mismatch — called exposure bias — means the model has never been trained to recover from its own mistakes. One wrong prediction cascades into increasingly wrong predictions. It's a fundamental problem with teacher forcing, and it partially motivated the move to non-autoregressive and diffusion-based approaches.
