# 17.1 Why Observability Matters

You can't debug what you can't see.

LLM calls are fundamentally opaque — the model's internal state, attention patterns, and reasoning process are invisible. You submit a prompt and receive a completion. When the agent does something wrong, the only way to understand why is to examine what actually happened: what inputs it received, what tools it called, what the tools returned, and what reasoning led to the final output.

Observability is how you make that reconstruction possible.

## The Three Signals

| Signal | Question Answered | Examples |
|--------|------------------|---------|
| **Traces** | What happened? | Full agent run record, tool call sequence, LLM inputs/outputs |
| **Metrics** | How much / how often? | Token counts, latency, cost, error rate, tool call frequency |
| **Logs** | Why? | Error details, security events, PII detections, anomalies |

All three are necessary. Traces without metrics don't scale. Metrics without traces don't explain. Logs without traces lose context.

## What Goes Wrong Without Observability

| Problem | Without Observability | With Observability |
|---------|-----------------------|-------------------|
| Agent gives wrong answer | "It just said the wrong thing" | "It called search_web, got a stale result, and used that as the basis for its response" |
| Agent is slow | "It's slow sometimes" | "The second LLM call averages 3.2s — it's waiting on the database tool" |
| Costs are rising | "Usage went up" | "Feature X uses 4x more tokens than feature Y; user cohort Z uses it 10x more" |
| Injection attack succeeded | "Something weird happened" | "At 14:32, the email fetcher returned content with a suspicious injection pattern; the agent called forward_email 30s later" |

## Observability is Not Optional for Production

For development, you can reconstruct behavior from print statements. For production:

- You cannot reproduce every user session for debugging
- You cannot ask users what input triggered the bug
- You cannot inspect the model's "reasoning" after the fact

Without traces and metrics, production incidents become guesswork.

> **The cost of not having observability is not zero.** It's the engineering hours spent debugging in the dark, the customer trust lost to unexplained failures, and the security incidents that go undetected until they become breaches.
