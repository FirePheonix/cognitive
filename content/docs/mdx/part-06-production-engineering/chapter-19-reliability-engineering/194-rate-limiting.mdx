# 19.4 Rate Limiting

LLM APIs impose rate limits on two dimensions: requests per minute (RPM) and tokens per minute (TPM). Hitting these limits causes 429 errors that interrupt user requests. The goal is to stay within limits proactively — not to handle 429s reactively.

## The Two Limits

| Limit Type | What It Counts | Typical Default (Claude Opus) |
|------------|---------------|-------------------------------|
| **RPM** — Requests Per Minute | API calls | 50–4,000 depending on tier |
| **TPM** — Tokens Per Minute | Input + output tokens combined | 200K–4M depending on tier |

TPM is usually the binding constraint for agents, because tool results inflate the input context significantly.

## Proactive vs Reactive

| Approach | When Action Taken | User Impact |
|----------|------------------|-------------|
| **Reactive** | After hitting 429 | Request fails, retry with backoff, user waits |
| **Proactive** | Before hitting limit | Slow down, queue, but no hard failures |

Proactive rate limiting is better. If you're at 80% of your TPM limit, slow down now — don't wait for the 429.

## Redis-Based Real-Time Tracking

```python
import redis
import time

class RateLimiter:
    def __init__(self, redis_client: redis.Redis):
        self.redis = redis_client

    def track_usage(self, tokens: int, model: str) -> None:
        """Record token usage for the current minute."""
        minute_key = f"tpm:{model}:{int(time.time() // 60)}"
        pipe = self.redis.pipeline()
        pipe.incrby(minute_key, tokens)
        pipe.expire(minute_key, 120)  # Keep for 2 minutes
        pipe.execute()

    def current_tpm(self, model: str) -> int:
        """Tokens used in the current minute."""
        minute_key = f"tpm:{model}:{int(time.time() // 60)}"
        return int(self.redis.get(minute_key) or 0)

    def should_throttle(self, model: str, tpm_limit: int, threshold: float = 0.8) -> bool:
        """
        Return True if we're above threshold% of our TPM limit.
        Throttle before hitting the hard limit, not after.
        """
        current = self.current_tpm(model)
        return current > (tpm_limit * threshold)

    def wait_if_needed(self, model: str, tpm_limit: int) -> None:
        """Block until we have headroom, with a maximum wait."""
        if not self.should_throttle(model, tpm_limit):
            return

        # Wait until the next minute window opens
        seconds_until_reset = 60 - (time.time() % 60)
        logger.info(
            f"TPM at {self.current_tpm(model):,}/{tpm_limit:,}. "
            f"Waiting {seconds_until_reset:.1f}s for window reset."
        )
        time.sleep(min(seconds_until_reset, 10))  # Wait max 10s per check
```

## Per-User Rate Limiting

Prevent single users from monopolizing your rate limit budget:

```python
USER_TOKEN_LIMIT_PER_HOUR = 100_000  # tokens per user per hour

def check_user_rate_limit(user_id: str, requested_tokens: int) -> bool:
    """Returns True if the user is within their rate limit."""
    hour_key = f"user_tph:{user_id}:{int(time.time() // 3600)}"
    current_usage = int(redis.get(hour_key) or 0)

    if current_usage + requested_tokens > USER_TOKEN_LIMIT_PER_HOUR:
        return False  # Would exceed limit

    pipe = redis.pipeline()
    pipe.incrby(hour_key, requested_tokens)
    pipe.expire(hour_key, 7200)  # 2-hour window
    pipe.execute()
    return True
```

## LiteLLM's Built-In Rate Limit Handling

LiteLLM handles rate limits automatically across providers, including automatic fallback to a secondary provider when the primary is rate limited:

```python
from litellm import completion
import litellm

# Enable automatic retry on rate limits
litellm.num_retries = 3

# Enable automatic fallback to secondary model on rate limit
response = completion(
    model="claude-opus-4-5",
    messages=messages,
    fallbacks=["gpt-4o", "claude-haiku-4-5-20251001"],  # Try these if rate limited
    metadata={"user_id": user_id},  # For per-user tracking
)
```

This is the simplest path if you're using LiteLLM — it handles the complexity of rate limit detection and fallback routing.

## Rate Limit Headers

LLM API responses include rate limit information in headers. Parse them to stay informed:

```python
# Anthropic response headers (approximate)
remaining_requests = response.headers.get("anthropic-ratelimit-requests-remaining")
remaining_tokens = response.headers.get("anthropic-ratelimit-tokens-remaining")
reset_at = response.headers.get("anthropic-ratelimit-requests-reset")
```
