# 13. The Training Loop

Chapter 12 established what we're optimizing: cross-entropy loss between the model's predictions and the actual next tokens. Now we need to actually do the optimizing.

The training loop is the mechanical heart of machine learning. It's a tight loop that runs the same five steps over and over, each time nudging the model's weights a tiny bit in the direction that reduces loss. Run it enough times on enough data, and the model goes from predicting random garbage to generating coherent text.

---

## The Five Steps

Every iteration of the training loop does exactly this:

![The five training steps — forward, loss, zero grads, backward, optimizer step — next to a learning-rate chart: linear warmup, then cosine decay from lr_max down to lr_min.](/appendix-d/13-the-training-loop/five-steps-and-lr.png)

Step 3 might look odd — why zero the gradients before the backward pass? Because PyTorch **accumulates** gradients by default. If you don't zero them, gradients from the previous batch add to the current batch's gradients, which is almost never what you want.

The reason this default exists is that sometimes you *do* want gradient accumulation — for example, when your GPU can't fit a large batch in memory and you want to simulate a larger batch by running several smaller batches before updating. But for the standard case, always zero first.

---

## Learning Rate Scheduling

The learning rate controls how big each weight update step is. Too large: the model overshoots, loss spikes, training can diverge. Too small: training is painfully slow.

The solution is to vary the learning rate over time. Modern LLMs use a schedule with two phases, drawn in the figure above.

**Warmup phase**: Start with a very small learning rate and linearly increase it to `lr_max` over the first few thousand steps. Why? At initialization, the model's weights are random. The gradients are noisy and unreliable. A large initial learning rate would destabilize training. Starting small lets the model find its footing.

**Cosine decay phase**: After warmup, smoothly decrease the learning rate following a cosine curve from `lr_max` down to `lr_min`. The cosine shape decays quickly at first (when there's still a lot to learn) and slowly at the end (fine-tuning the final details).

---

## Gradient Clipping

During backpropagation, gradients can occasionally be very large — especially early in training or when the model encounters unusual data. Applying a huge gradient update can catastrophically destroy the weights that were working well.

**Gradient clipping** prevents this: before each optimizer step, if the global norm of the gradient vector exceeds a threshold (typically 1.0), scale all gradients down so the norm equals exactly 1.0.

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
```

This doesn't change the *direction* of the gradient, just its *magnitude*. The model still moves in the right direction, just not too far in one step.

## Why AdamW?

The optimizer used above is **AdamW**. It's a variant of Adam (Adaptive Moment Estimation) with one important fix: proper weight decay.

Regular Adam absorbs weight decay into the adaptive learning rate calculation, which reduces its effectiveness. AdamW applies weight decay directly to the weights, independently of the gradient:

```
weight_new = weight_old × (1 - lr × weight_decay) - lr × gradient
```

The `weight_decay` term (typically 0.01 to 0.1) acts as a gentle regularizer: it continuously pulls weights toward zero, preventing any single weight from becoming too large. For language models, this reduces overfitting and improves generalization.

## Batch Size, Gradient Accumulation, and Effective Batch Size

GPT-3 was trained with a batch size of 3.2 million tokens per step. A modern GPU might hold 32 sequences of 1024 tokens, or about 32,768 tokens per batch. That's a 100× gap.

The solution is **gradient accumulation**: run N small forward/backward passes without calling `optimizer.step()`, let the gradients accumulate, then step once. The accumulated gradient is mathematically equivalent to a single forward pass with N× the batch size.

```python
accumulate_steps = 128  # effective batch size = batch_size × 128

optimizer.zero_grad()
for micro_step in range(accumulate_steps):
    x, y = get_batch(...)
    loss = model(x, y) / accumulate_steps  # normalize by number of steps
    loss.backward()                         # gradients accumulate

torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

Large batch sizes stabilize training and allow higher learning rates. GPT-3's enormous batch size was one of the factors that made it trainable with a consistent learning rate throughout.

## Quick Recap

- The training loop is: forward → loss → zero_grad → backward → step. Repeat billions of times.
- **Always zero gradients before backward** (unless intentionally accumulating).
- **Learning rate warmup** lets the model stabilize before taking large steps. Typically 1-5% of total training steps.
- **Cosine decay** smoothly reduces the learning rate over training, allowing fine-grained adjustments later in training.
- **Gradient clipping** (max norm = 1.0) prevents catastrophic weight updates from large gradient spikes.
- **AdamW** is the standard optimizer: adaptive per-parameter learning rates + proper weight decay.
- The loss going from 3.95 to 1.13 is not just a number — it means the model went from random guessing to having strong preferences about what comes next.
