# 11. GPT Architecture

GPT stands for Generative Pre-trained Transformer. The architecture is simpler than you might expect: it's just transformer blocks stacked on top of each other, with token embeddings at the input and a linear projection to vocabulary size at the output. No encoder. No cross-attention. Just decoder blocks all the way.

That simplicity is the point. The decoder-only design is what makes GPT a language model — a machine that, given some tokens, predicts the next one.

The 2018 paper that named the pattern is Radford, Narasimhan, Salimans and Sutskever, *Improving Language Understanding by Generative Pre-Training* — GPT-1. A Transformer decoder, language-model pre-training on BooksCorpus, then a small fine-tune on each GLUE-style task.

## What "Decoder-Only" Actually Means

The original transformer (Vaswani et al., 2017) had two halves: an **encoder** that reads a source sequence and a **decoder** that generates a target sequence while attending to the encoder's output. That architecture was designed for machine translation: read an English sentence (encoder), generate a French sentence (decoder).

GPT throws out the encoder entirely. There's no source sequence to read. The model just takes a sequence of tokens and predicts what comes next. This is all you need for language modeling.

The "decoder" name is kept because GPT uses causal (masked) self-attention — the same attention mask used in the original decoder to prevent positions from attending to future positions. Each token can only see the tokens that came before it.

![GPT as a stack of decoder blocks: token IDs through embeddings, N transformer blocks, final LayerNorm, a weight-tied LM head, and logits. Beside it, the original encoder–decoder: source through an encoder, target through a decoder, with K and V flowing across. A note on why decoder-only won: one stack, one unlabeled objective.](/appendix-d/11-gpt-architecture/decoder-only-stack.png)

The encoder can see all positions in both directions (bidirectional attention). The GPT decoder can only see positions to its left (causal attention). That's the core structural difference.

---

## Why Decoder-Only Predicts Text

Here's the key insight: **next-token prediction is all you need to learn language**.

If a model can accurately predict the next token given all previous tokens, it must have learned:
- Grammar (some words are grammatically valid continuations, others aren't)
- Facts (after "The capital of France is", "Paris" is far more likely than "banana")
- Reasoning patterns (if-then structures, logical continuations)
- Style and tone

The causal mask enforces this. At training time, position 5 can only see positions 1-4. It never cheats by looking at position 6. At inference time, we really are generating left to right — there are no future tokens to see.

Let's trace a concrete example: the string `"The cat sat"` passed through a small GPT.

![One forward pass of “The cat sat”: text → token IDs [464, 3797, 3332] → embed + positions [1, 3, 768] → 12 blocks (same shape) → LM head [1, 3, 50,257]. A causal mask heatmap for length 4, and the three architecture families: encoder-only, decoder-only, encoder–decoder.](/appendix-d/11-gpt-architecture/forward-pass-and-mask.png)

![The LM head is one matrix multiply. Tiny vocab {The, cat, sat, .}: embedding matrix E (4×3) looks up rows for token IDs [0,1,2] into X (3×3). Logits = X Eᵀ (3×4). Worked cell: logits[sat, cat] = [1,1,0]·[0,2,0] = 2. Generation softmaxes only the last row.](/appendix-d/11-gpt-architecture/lm-head-matmul.png)

During training, we compare position 0's prediction to the actual token at position 1, position 1's prediction to position 2, and so on. This is the "shift by one" structure — one forward pass generates training signal for every position in the sequence simultaneously. The figure is the same multiply with a 4-word vocab so you can check every cell.

The FFN holds nearly half the parameters. This isn't a surprise — each transformer block has a feed-forward network with 8× the parameter count of the attention (4D² attention vs 8D² FFN). Research by Geva et al. (2021) suggests these FFN parameters function as "key-value memories" that store factual associations — the FFN is where much of a model's world knowledge lives.

## The Causal Mask in Detail

The causal mask is what enforces the "can only look backward" property. It's a lower-triangular matrix applied to the attention scores before softmax. Zeros become −∞ before softmax, so future tokens get probability 0.

![Causal attention by hand. Q and K for The/cat/sat, scores S = QKᵀ with S[cat,cat] = 4, future cells set to −∞, then softmax. “The” attends only to itself; “sat” may mix all three. Output is still O = AV — another matmul.](/appendix-d/11-gpt-architecture/causal-qk-matmul.png)

This is efficient: you can train on a sequence of 1024 tokens and get 1024 prediction targets simultaneously, all from one forward pass. Position 0 predicts position 1. Position 1 predicts position 2. And so on. No cheating — the mask guarantees position `i` only uses information from positions `0..i`. The grids above are that multiply for length 3; the earlier heatmap is the same mask for length 4.

## Why This Architecture Became Dominant

There are three reasons the decoder-only architecture took over:

**1. Simplicity scales well.** The original encoder-decoder had two separate sets of parameters and cross-attention between them. A decoder-only model is one unified stack — easier to scale, easier to reason about, and (empirically) equally capable when scaled up.

**2. Pretraining is a single objective.** Next-token prediction requires no labeled data, no human annotations, no task-specific design. You just throw text at it. The internet has roughly 100 trillion tokens of text. That's your training data.

**3. Emergent generalization.** A model trained only to predict the next token turns out to be able to answer questions, write code, translate text, and summarize documents — without any task-specific training. This emerged from scale, not from explicit programming.

GPT-2 (2019) demonstrated this with a 1.5B parameter model. GPT-3 (2020) showed it dramatically at 175B. Every major LLM since — LLaMA, Mistral, Claude, Gemini — uses this same decoder-only architecture.

## Quick Recap

- **Decoder-only** means causal (masked) self-attention with no encoder. Each token can only attend to previous tokens.
- The data flow is: token IDs → embeddings + positional encoding → N transformer blocks → final LayerNorm → LM head → logits.
- **Logits** are raw scores over the vocabulary. Softmax converts them to probabilities. During training, we use the logits directly in cross-entropy loss.
- The **LM head is weight-tied** with the token embedding matrix — no extra parameters.
- GPT-3 175B uses the same architecture as GPT-2 small, just with 96 layers, d_model=12288, and n_heads=96 instead of 12/768/12.
- The FFN holds ~45% of all parameters and is where most of the model's "knowledge" appears to be stored.

## Three Architecture Families: A Comparison

There are three fundamentally different ways to build a Transformer, each with different information visibility and best-suited tasks:

| Architecture | Objective | Attention Mask | Representative Models | Best For |
|---|---|---|---|---|
| **Encoder-only** | Masked LM (predict masked tokens) | Bidirectional (sees all tokens) | BERT, RoBERTa | Classification, NER, embeddings |
| **Decoder-only** | Causal LM (predict next token) | Causal (sees only past tokens) | GPT, Llama, Claude | Generation, chat, reasoning |
| **Encoder-Decoder** | Denoising / seq-to-seq | Encoder: bidirectional; Decoder: causal + cross-attention | T5, BART | Translation, summarization |

BERT (Devlin et al., 2018) is the encoder-only twin of GPT: same Transformer block, bidirectional attention, trained to fill in masked tokens and to classify sentence pairs.

**The key insight about information visibility:**
- Encoder models see the whole sentence at once — great for understanding a fixed input
- Decoder models only see what came before — necessary for generation (you can't cheat and read the future)
- Encoder-decoder models combine both — encoder reads the source, decoder generates the target

**Why decoder-only won:**
Despite starting as "just the decoder half," decoder-only models turned out to be remarkably general. With enough scale, a model trained purely on "predict the next token" learns to do translation, summarization, coding, and reasoning — without any task-specific architecture. The simplicity is the feature.

The causal LM objective:
$$\mathcal{L}_{\text{CLM}} = -\sum_t \log P(x_t \mid x_{<t})$$
Every sentence in every document is training data. No labels needed. At trillion-token scale, this simple objective produces surprisingly general capabilities.
