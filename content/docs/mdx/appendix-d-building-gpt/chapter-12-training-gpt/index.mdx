# 12. Training GPT — Data and the Objective

Before a GPT model can do anything useful, it has to be trained. Training means running a lot of text through the model, measuring how wrong its predictions are, and adjusting the weights to make them less wrong. Do this billions of times and the model gets good at predicting text — which turns out to be the same as learning language.

This chapter covers the first half of training: what the data looks like, how input/target pairs are constructed, and how cross-entropy loss quantifies "how wrong" the model is.

---

## What Training Data Looks Like

Training data is just text — enormous amounts of it. GPT-2 was trained on WebText (~40GB, 8M web documents). GPT-3 was trained on ~300 billion tokens from the internet, books, Wikipedia, and code.

But the model doesn't see raw text. It sees **token IDs**. Before training begins, every document is tokenized:

```
Raw text:    "First Citizen: Before we proceed any further, hear me speak."

GPT-2 BPE:  ["First", " Citizen", ":", " Before", " we", " proceed",
              " any", " further", ",", " hear", " me", " speak", "."]

Token IDs:  [5962, 22307, 25, 5075, 356, 5120, 597, 2252, 11, 3285, 502, 2740, 13]
```

The entire training corpus becomes one gigantic sequence of integers. GPT-3's 300B tokens means a sequence of 300,000,000,000 integers. Training samples are windows sliced from this sequence.

---

## Creating Input/Target Pairs

The training objective is next-token prediction: given tokens 1 through N, predict token N+1. This means for every training sample, the **target is just the input shifted by one position**.

```
Input sequence:   [The,  cat,  sat,  on,  the,  mat]
Token IDs:        [464, 3797, 3332,  319,  262, 2603]

Input  (feed to model):  [464, 3797, 3332,  319,  262]
Target (what to predict): [3797, 3332,  319,  262, 2603]
```

Position 0 of input is `464` ("The") → model should predict `3797` ("cat")  
Position 1 of input is `3797` ("cat") → model should predict `3332` ("sat")  
Position 2 of input is `3332` ("sat") → model should predict `319` ("on")  
And so on.

This is why one sentence generates multiple training examples: a sequence of length N gives N-1 input/target pairs, all computed in a single forward pass thanks to the causal mask.

## Cross-Entropy Loss: Measuring Surprise

After the forward pass, the model produces logits — one score per vocabulary token, per position. The training objective is to make the correct next-token score as high as possible.

**Cross-entropy loss** formalizes this. It measures how "surprised" the model is at seeing the correct next token:

```
loss = -log(P(correct_token))

If P(correct_token) = 0.9  → loss = -log(0.9)  = 0.105  (not very surprised)
If P(correct_token) = 0.1  → loss = -log(0.1)  = 2.303  (quite surprised)
If P(correct_token) = 0.02 → loss = -log(0.02) = 3.912  (very surprised)
```

For a vocabulary of 50,000 tokens, a random model assigns probability ~1/50000 = 0.00002 to each token. That gives a loss of:

```
-log(1/50000) = log(50000) ≈ 10.8
```

So a freshly initialized GPT-2 has a loss of roughly 10.8. After training on good data, a well-trained model achieves losses around 2-3. The difference in loss directly translates to probability: at loss 2.3, the model assigns average probability ~10% to the correct token, which means it has a genuine sense of what's likely to come next.

## Why This Objective Is So Powerful

Next-token prediction sounds deceptively simple. You're just teaching the model to guess the next word. But to guess the next word accurately, you need to understand:

- **Grammar**: "The dog run" is wrong, "The dog runs" is right
- **Facts**: After "The capital of Japan is", the answer is "Tokyo"
- **Coreference**: "Alice went to the store. She bought milk." — "She" = "Alice"
- **Reasoning**: "If it rains, I'll bring an umbrella. It's raining. Therefore I'll bring ___"
- **Style**: A Shakespeare play continues differently than a Python tutorial

None of these were explicitly programmed. They all emerged from the single objective of predicting the next token, applied to enough diverse text. This is why GPT-3 can translate French, write code, and answer trivia questions without being explicitly trained on any of those tasks.

## Quick Recap

- Training data is text tokenized to integer sequences. For GPT-3: ~300 billion integers.
- Input/target pairs are created by **shifting the sequence left by 1**: `input = tokens[i:i+n]`, `target = tokens[i+1:i+n+1]`.
- The causal mask means one forward pass gives you N-1 training examples from a sequence of length N.
- **Cross-entropy loss** = `-log(P(correct_token))`. High probability on the correct token → low loss.
- A random model starts at loss `log(vocab_size)`. For GPT-2's vocab: `log(50257) ≈ 10.8`.
- After training, a good model achieves loss ~2-3, meaning it has learned genuine preferences about what comes next.

## Scaling Laws: Why Bigger Usually Means Better

One of the most important empirical findings in modern ML: model performance (measured as loss) scales predictably with model size, data size, and compute — following power laws.

**The Chinchilla scaling laws:**
$$L(N) \approx L_\infty + aN^{-\alpha}$$
$$L(D) \approx L_\infty + bD^{-\beta}$$
Where $N$ is parameter count, $D$ is token count, $L_\infty$ is the irreducible loss, and $\alpha, \beta$ are fitted exponents (empirically around 0.3–0.5).

What this says: doubling model size reduces loss by a predictable, consistent amount. So does doubling training data.

**The compute-optimal insight (Chinchilla):**
The crucial finding from DeepMind's "Chinchilla" paper: previous models were undertrained. The optimal tradeoff is roughly: for every 10× increase in compute, you should scale both parameters and training tokens by about 3.16× each (roughly equal in log space).

GPT-3 (175B parameters, 300B tokens) was trained with too many parameters for too few tokens. A compute-matched model with fewer parameters and more data would have been better.

**What the data pipeline actually does:**
Modern pretraining data isn't "just the internet." It goes through:
```
Web crawl
→ Language identification (keep English, etc.)
→ Quality filtering (remove spam, adult content, boilerplate)
→ Deduplication (exact and near-duplicate removal)
→ Safety/privacy filtering
→ Mixture weighting (weight Wikipedia more than random forum posts)
→ Tokenization
```
Data quality is arguably more important than quantity. A model trained on carefully curated 1T tokens will outperform one trained on noisy 2T tokens.
