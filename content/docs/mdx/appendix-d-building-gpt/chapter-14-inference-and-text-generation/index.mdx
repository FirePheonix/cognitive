# 14. Inference and Text Generation

A trained GPT model outputs a probability distribution over the vocabulary at every position. To generate text, you have to actually make a choice: which token comes next? That choice is called **decoding**, and there are several ways to make it.

The difference between a model that outputs boring, repetitive text and one that generates creative, coherent prose is often not the model itself — it's the decoding strategy.

---

## Autoregressive Generation

GPT generates text one token at a time. Each new token is appended to the sequence, and the whole sequence (prompt + generated tokens so far) is fed back through the model to predict the next one.

![Generate loop: prompt → forward (use last-position logits) → sample (greedy / temperature / top-k / top-p) → append and loop. A bar chart of an example distribution (the 0.70, a 0.20, my 0.06, purple 0.04) and a comparison of top-k vs top-p.](/appendix-d/14-inference-and-text-generation/generate-and-sample.png)

![Generation softmaxes only the last logits row. A 3×4 matrix after “The cat sat”; the last row [2.1, 0.8, −0.4, −1.2] is divided by temperature T and softmaxed. T = 0.5 peaks on “the”; T = 2 flattens the same vector. Greedy is argmax of that row.](/appendix-d/14-inference-and-text-generation/sample-by-hand.png)

Why do we use only the last position's logits? Because the causal mask means position `T` has seen all positions `0..T`. Its logits represent the distribution over the next token given everything that came before. That's exactly what we want. The figure is that last row, written out.

This is inefficient — we recompute attention for all previous tokens at every step. In practice, models use a **KV cache** that stores the key and value vectors from previous steps, so each new step only requires computing attention for the new token. But the logic is the same.

---

## Greedy Decoding

The simplest strategy: always pick the token with the highest probability.

```python
next_token = logits.argmax(dim=-1)
```

**Advantage**: Fast, deterministic.  
**Problem**: Greedy decoding tends to produce repetitive, stilted text. Once the model finds a common phrase, it keeps repeating it because high-probability completions lead to more high-probability completions.

```
Prompt: "The sky is"
Greedy: "The sky is the most beautiful thing in the world. The sky is the most beautiful thing in the world. The sky is..."
```

---

## Temperature Sampling

Rather than always picking the top token, sample from the distribution — but control how sharp or flat that distribution is using a **temperature** parameter.

```
logits_scaled = logits / temperature
probs = softmax(logits_scaled)
next_token = sample(probs)
```

- **temperature = 1.0**: Sample from the model's learned distribution as-is. Natural randomness.
- **temperature < 1.0**: Sharpen the distribution. High-probability tokens become *more* likely. Makes output more predictable and conservative.
- **temperature > 1.0**: Flatten the distribution. Unlikely tokens get a bigger chance. More creative, more chaotic.

```
Vocabulary: [the=0.7, a=0.2, my=0.06, purple=0.04]   (before temperature)

temperature=0.5:  [the=0.94, a=0.06, my=0.00, purple=0.00]   (peaked)
temperature=1.0:  [the=0.70, a=0.20, my=0.06, purple=0.04]   (original)
temperature=1.5:  [the=0.55, a=0.27, my=0.10, purple=0.08]   (flattened)
temperature=2.0:  [the=0.44, a=0.31, my=0.14, purple=0.11]   (very flat)
```

At very high temperatures, the model samples almost uniformly — high entropy, incoherent output. At very low temperatures, it converges to greedy decoding.

---

## Top-K Sampling

Keep only the `k` most likely tokens, set everything else to zero probability, then sample.

```
k=5: Only consider the top 5 tokens. Ignore the rest.
     This prevents the model from generating very unlikely tokens.
     But if the distribution is already concentrated (1 token has 95% prob),
     keeping 5 tokens means 4 are near-zero anyway.
```

Top-k is simple and effective but has a fixed threshold that doesn't adapt to the model's confidence. When the model is very confident (peaked distribution), k=50 still allows 49 unlikely alternatives. When the model is uncertain (flat distribution), k=50 might cut off reasonable choices.

Using the same four-word distribution as the figure above (`the=0.70, a=0.20, my=0.06, purple=0.04`) and `k = 2`:

![Top-k step 1. Keep the two biggest probabilities (the, a) and set my and purple to zero. Those two still had 10% of the mass; with a hard cutoff they can never be sampled this step.](/appendix-d/14-inference-and-text-generation/topk-step-1-keep-k.png)

![Top-k step 2. Re-normalize what survived: divide by 0.70 + 0.20 = 0.90. P′(the) ≈ 0.78, P′(a) ≈ 0.22. Now you can sample.](/appendix-d/14-inference-and-text-generation/topk-step-2-renorm.png)

## Top-P (Nucleus) Sampling

Instead of fixing the number of candidates, fix the cumulative probability. Keep the smallest set of tokens whose cumulative probability exceeds `p`.

```
Sorted tokens:  [the=0.70, a=0.20, my=0.06, purple=0.04]

top_p=0.90:  Keep [the, a] (cumsum: 0.70 + 0.20 = 0.90) — 2 tokens
top_p=0.97:  Keep [the, a, my] (cumsum: 0.96) — 3 tokens
top_p=0.99:  Keep [the, a, my, purple] (cumsum: 1.00) — 4 tokens
```

![Top-p (nucleus): sort descending and keep adding until the running sum reaches p = 0.90. “the” (cum 0.70) still under, “a” hits 0.90 and we stop. “my” and “purple” drop. Include the token that crosses p, then re-normalize.](/appendix-d/14-inference-and-text-generation/topp-nucleus-cumsum.png)

When the model is confident, top-p selects a small set (high confidence = fewer candidates needed to reach p). When the model is uncertain, top-p selects a larger set (spread distribution = more candidates needed).

Top-p adapts to the model's confidence. It's the default in most production systems.

## When to Use Each Strategy

| Strategy | Temperature | Top-K | Top-P | Best For |
|:---------|:------------|:------|:------|:---------|
| Greedy | 0 | — | — | Deterministic tasks, debugging, beam search |
| Conservative | 0.3–0.5 | — | — | Factual Q&A, code completion |
| Balanced | 0.7–1.0 | — | 0.9–0.95 | General text, chat |
| Creative | 1.0–1.3 | — | 0.95 | Creative writing, brainstorming |
| High-entropy | 1.5+ | 50 | — | Exploration, diversity sampling |

In practice, most production systems use **temperature=0.7-1.0 with top-p=0.9-0.95** and leave top-k disabled. Top-p handles the adaptive cutoff better than a fixed top-k.

---

## Quick Recap

- Generation is **autoregressive**: the model generates one token at a time, feeding each generated token back as part of the next input.
- Only the **last position's logits** are used at each step — that's the distribution over the next token.
- **Greedy** (argmax) is deterministic but produces repetitive output.
- **Temperature** sharpens (< 1) or flattens (> 1) the distribution before sampling.
- **Top-k** limits candidates to the k most likely tokens.
- **Top-p (nucleus)** adapts the candidate set to the model's confidence — fewer candidates when confident, more when uncertain. This is the most widely used strategy.
- For factual tasks, use lower temperature. For creative tasks, use higher temperature. For most general-purpose generation: temperature=0.7-1.0, top-p=0.9.
