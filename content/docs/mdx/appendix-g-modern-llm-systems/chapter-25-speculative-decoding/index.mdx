# 25. Speculative Decoding

KV cache eliminates redundant computation. Quantization shrinks the model. But neither removes the core bottleneck of autoregressive generation: tokens are produced **one at a time**, each requiring a full forward pass through all transformer layers.

You can't skip steps. Token `t+1` depends on token `t`. The architecture enforces this — it's not a bug you can fix with engineering tricks at the hardware level.

But there's a clever workaround: what if you *guessed* the next several tokens with a small, cheap model — then verified all the guesses at once with the large, accurate model?

---

## The Intuition

Here's the key observation: the large model is slow not because of the *number of tokens* it processes per forward pass — it's slow because of the *number of forward passes*. If you can get multiple tokens out of a single forward pass, you've won.

![Speculative decoding: a small draft model guesses K tokens; the large target model verifies all K in one parallel pass. Accept the prefix that matches, sample a correction at the first reject. Output distribution matches the target model alone.](/appendix-g/25-speculative-decoding/draft-and-verify.png)

```text
Normal autoregressive generation (generating 4 tokens):

  Pass 1: input = [prompt]              → output = token_1       (1 pass, 1 token)
  Pass 2: input = [prompt + token_1]    → output = token_2       (2nd pass, 1 token)
  Pass 3: input = [prompt + 1 + 2]      → output = token_3       (3rd pass, 1 token)
  Pass 4: input = [prompt + 1 + 2 + 3]  → output = token_4       (4th pass, 1 token)
  
  Total: 4 large-model forward passes → 4 tokens

Speculative decoding:

  Draft pass:  small model quickly guesses [d₁, d₂, d₃, d₄]
  
  Verify pass: large model processes [prompt + d₁ + d₂ + d₃ + d₄] in ONE pass
               → gets predictions at all 4 positions simultaneously
               → check which guesses were right
               
  If all 4 correct: 1 large-model pass → 4 tokens  (4× speedup this round)
  If first 2 correct: 1 large-model pass → 2 tokens + 1 corrected  (3× speedup)
  If none correct: 1 large-model pass → 1 corrected token  (1× — same as before)
```

The key insight: the large model's verify pass is **no more expensive than a normal generation step** — it processes `(prompt + K draft tokens)` in parallel during the prefill phase. You get K chances to accept tokens for the cost of one pass.

---

## How Acceptance Works (the Math)

The most important property of speculative decoding: done correctly, the output **distribution is identical** to running the large model alone. It's not an approximation. You don't lose quality.

The acceptance rule:

```text
Given draft token x at position i:
  p_draft(x)  = probability the draft model assigned to x
  p_target(x) = probability the large model assigns to x at this position

Accept x with probability:  min( 1,  p_target(x) / p_draft(x) )

If p_target(x) ≥ p_draft(x):  accept always   (ratio ≥ 1)
  → The draft was conservative. The large model agrees or is even more confident.

If p_target(x) < p_draft(x):  accept with probability p_target/p_draft
  → The draft was overconfident. We probabilistically reject to avoid bias.

At the first rejection: don't stop! Sample a corrected token from the large model.
Continue to the next round of drafting.
```

```text
Example with 4 draft tokens:

  position   token   p_draft   p_target   ratio   accept?
  ─────────────────────────────────────────────────────────
     0         15     0.80      0.90      1.125   always ✅
     1         23     0.70      0.80      1.143   always ✅
     2          8     0.60      0.20      0.333   33% chance ← let's say: REJECT ❌
     3         42     0.50      0.10      0.200   (not evaluated, stopped at 2)

  Result:
    - Tokens 15 and 23 accepted
    - Large model samples a corrected token at position 2
    - 1 target forward pass → 3 tokens (2 accepted + 1 corrected)
```

The mathematics ensure that the joint distribution over accepted tokens equals what you'd get from running the target model alone. No quality compromise.

## Why the Output Distribution Is Preserved

This is worth proving, because it's non-obvious.

```text
CLAIM: speculative decoding produces the same distribution as the target model alone.

PROOF sketch for one token:

  Without speculative decoding:
    sample from target distribution:  P(token = x) = p_target(x)

  With speculative decoding, token x is accepted when:
    - draft produces x (probability p_draft(x))
    - acceptance test passes (probability min(1, p_target(x)/p_draft(x)))
    
    Accept probability = p_draft(x) × min(1, p_target(x)/p_draft(x))
                       = min(p_draft(x), p_target(x))

  Token x can also reach output via the correction step (at rejection):
    Total probability of x = min(p_draft(x), p_target(x)) 
                           + residual from correction term
    
    = p_target(x)   ← after the math works out exactly

The two paths (accept + correction) combine to reproduce p_target exactly.
This is why speculative decoding is exact — the correction step is critical.
```

In practice: if the draft model is "overconfident" (assigns high probability to wrong tokens), rejection is more frequent. The correction step then samples from the target distribution, preserving correctness at the cost of less speedup.

## When to Use Speculative Decoding

```text
Good fit:
  + Output is somewhat predictable (code, structured formats, formulaic text)
  + You have a well-matched smaller model from the same family
    (Llama-7B drafting for Llama-70B, Codestral-7B for Codestral-22B)
  + Batch size is small (latency-focused serving)

Poor fit:
  - Highly creative/random outputs (high temperature) — draft always wrong
  - Batch size is large — batching already fills the GPU; no benefit
  - No suitable draft model available
  - Memory-constrained — running both draft + target simultaneously costs extra VRAM

Typical real-world speedup: 2-3× for code, 1.5-2× for general text
```

## Quick Recap

- Autoregressive generation is bottlenecked by the **number of target-model forward passes**, not the number of tokens per pass.
- Speculative decoding uses a **small draft model** to guess K tokens cheaply, then verifies all K in **one target-model forward pass**.
- Acceptance rule: accept token `x` with probability `min(1, p_target(x) / p_draft(x))`. If rejected, sample a corrected token from the target distribution.
- **Output distribution is mathematically identical** to running the target model alone — the correction step ensures this. Not an approximation.
- Speedup depends on **acceptance rate** — how often the draft model's guesses match the target's preference. High agreement → high speedup. Very different models → no benefit.
- Real-world: 2–3× speedup for code generation with matched model families. Best results with same-family models (7B drafting for 70B).

## The Formal Acceptance Rule and Why It's Lossless

The magic of speculative decoding is that it's mathematically guaranteed to produce the same distribution as the target model alone — it's not an approximation. Here's why.

**The acceptance criterion:**
For each draft token $x$ proposed by the small draft model $p$, the target model $q$ computes its own probability. The acceptance rule is:
$$\alpha(x) = \min\left(1, \frac{q(x)}{p(x)}\right)$$

- If $q(x) \ge p(x)$: accept with probability 1 (the target model would have been at least as likely to generate this)
- If $q(x) < p(x)$: accept with probability $q(x)/p(x)$ (the target model is less enthusiastic — accept proportionally)

When a token is rejected, you don't give up — you resample from the corrected distribution $q(x) - p(x)$ (normalized), ensuring the final output distribution matches the target exactly.

**The key efficiency metric: acceptance rate:**
$$A = \frac{\text{accepted draft tokens}}{\text{proposed draft tokens}}$$

If $A = 0.8$ and you propose $K=4$ tokens per draft step, you accept on average 3.2 tokens per target model call instead of 1. That's a 3.2× speedup in tokens per second.

The acceptance rate depends entirely on how similar the draft model is to the target. A 7B draft model used with a 70B target typically achieves $A \approx 0.7$–$0.85$ for natural language.

**Why this works at all (the intuition):**
Most of the time, the next token isn't surprising. "The cat sat on the ____" — "mat", "floor", "couch" are all very predictable. A small, fast model gets these easy tokens right almost always. The expensive target model is only "needed" for the hard, uncertain tokens. Speculative decoding exploits this asymmetry.

**Dynamic speculation:**
Fixed lookahead $K$ isn't optimal. Easy positions (high confidence) deserve more draft tokens; hard positions (high entropy) should use fewer, because draft tokens will mostly be rejected anyway. Adaptive speculation adjusts $K$ based on the draft model's confidence, maximizing accepted tokens per target model call.
