# 21.3 Secret Management

API keys, database credentials, and other secrets should never appear in agent context — not in the system prompt, not in tool arguments, not in log output. If they do, they will eventually leak.

## The Core Principle

> **Give agents capabilities, not credentials.**

An agent should receive a pre-configured database client, not a connection string. It should receive a pre-authenticated HTTP client, not an API key. The agent never sees the credential — it only sees the capability the credential enables.

```python
# BAD: agent receives raw credentials
agent = CustomerServiceAgent(
    system_prompt=f"""
    You are a customer service agent.
    Database: postgres://admin:{DB_PASSWORD}@prod-host:5432/customers
    API key: sk-live-{PAYMENT_API_KEY}
    """,
)

# GOOD: agent receives pre-configured clients
db_client = create_db_client()          # connection string loaded internally
payment_client = create_payment_client() # API key loaded internally

agent = CustomerServiceAgent(
    tools=[
        CustomerLookupTool(db_client),   # tool wraps the client
        PaymentTool(payment_client),
    ],
)
```

## The `.env` Pattern

Load secrets from environment variables at startup. Never hardcode. Never log.

```python
# atlas-agents/shared/config.py

import os
from pathlib import Path
from dotenv import load_dotenv

# Load .env file if present (development)
load_dotenv()

def require_key(key_name: str) -> str:
    """
    Load a required secret from the environment.
    Fails loudly with a clear error message if missing.
    Never returns None silently.
    """
    value = os.environ.get(key_name)
    if not value:
        raise EnvironmentError(
            f"Required environment variable '{key_name}' is not set. "
            f"Add it to your .env file or set it in your deployment environment."
        )
    return value

def optional_key(key_name: str, default: str = "") -> str:
    """Load an optional secret, returning default if not set."""
    return os.environ.get(key_name, default)
```

```python
# Usage — fail loudly at startup, not at runtime
ANTHROPIC_API_KEY = require_key("ANTHROPIC_API_KEY")
DATABASE_URL      = require_key("DATABASE_URL")
REDIS_URL         = optional_key("REDIS_URL", "redis://localhost:6379")
```

## The `.gitignore` Rule

```gitignore
# .gitignore — never commit secrets
.env
.env.*
!.env.example    # commit the template, not the values
*.key
*.pem
secrets/
```

```bash
# .env.example — commit this as documentation
ANTHROPIC_API_KEY=your-anthropic-api-key-here
DATABASE_URL=postgres://user:password@host:5432/dbname
REDIS_URL=redis://localhost:6379
```

## Production Secret Management

For production deployments, `.env` files are insufficient. Use a secrets management service:

| Platform | Service | How to use |
|----------|---------|-----------|
| AWS | Secrets Manager | `boto3.client('secretsmanager').get_secret_value(...)` |
| GCP | Secret Manager | `secretmanager.SecretManagerServiceClient().access_secret_version(...)` |
| HashiCorp Vault | Vault | `hvac.Client().secrets.kv.read_secret_version(...)` |
| Kubernetes | Secrets | Mounted as environment variables or volumes |

```python
# AWS Secrets Manager integration
import boto3
import json

def load_secret(secret_name: str, region: str = "us-east-1") -> dict:
    client = boto3.client("secretsmanager", region_name=region)
    response = client.get_secret_value(SecretId=secret_name)
    return json.loads(response["SecretString"])

# At startup — secrets are fetched once, not stored in agent context
secrets = load_secret("prod/atlas-agents/api-keys")
anthropic_client = Anthropic(api_key=secrets["ANTHROPIC_API_KEY"])
```

## What Not to Do

| Anti-pattern | Risk |
|-------------|------|
| Hardcode API keys in source | Key in git history forever |
| Log request headers | Bearer tokens in log files |
| Pass credentials in tool arguments | Credentials in LLM context and trace logs |
| Store keys in system prompt | Exposed via prompt leakage |
| Print credentials in error messages | Credentials in stdout/stderr logs |

## Detecting Accidental Credential Exposure

Add a check to your output filter for patterns that look like credentials:

```python
CREDENTIAL_PATTERNS = {
    "anthropic_key": r"sk-ant-[a-zA-Z0-9\-_]{40,}",
    "openai_key":    r"sk-[a-zA-Z0-9]{48}",
    "aws_key":       r"AKIA[0-9A-Z]{16}",
    "generic_secret": r"(?i)(password|secret|token|key)\s*[:=]\s*\S{8,}",
}
```

Any match in agent output is a critical incident.
